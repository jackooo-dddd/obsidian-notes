# 项的构造
> Π 是类型论里的一个项构造器，构造出来的项用来表示类型（依赖函数类型）。不过构造器只负责拼，拼出来的项只有满足 Π 的**形成规则**，才是合法的类型：A 必须是类型，在 `x:A` 下 B 也必须是类型，满足后整个 Π 的类型就是某个 Sort。
> 在 Rocq 里，`Prod` 就是对应的构造器，可以拼出任意形状的项。为了确保它拼出的项符合 Π 的形成规则，kernel 的类型检查代码里有一个 `Prod` 分支，专门检查这条规则，并通过 `sort_of_product` 算出结果的 Sort。
> Lean 的思路完全一样：`forallE` 是 `Expr` 的构造子，和 Π 一样构造出表示类型的项；`infer_pi` 负责检查形成规则，并用 `imax` 算出结果的 Sort。
> λ 也是同一个模式：`Lambda`/`lam` 是构造器，构造出表示函数（值）的项；`Lambda` 分支和 `infer_lambda` 负责检查引入规则，检查的结果就是一个 Π 类型。
## 能造出来 ≠ 合法
构造器只管"拼"。只要给 Π 一个参数名和两个项 A、B，就能拼出 `Πx:A. B`，哪怕 A 根本不是类型：

```
Πx:O. nat        ← 语法上拼得出来，但 O 是一个自然数，不是类型
```
所以类型论把项分成两层：

| 层次 | 怎么得到 | 例子 |
|---|---|---|
| **预项**（raw term） | 按语法用构造器拼出来，不做任何检查 | `Πx:O. nat` 也算 |
| **合法的项**（良类型项） | 预项中能通过类型规则推出类型的那些 | `Πx:nat. nat` 合法，`Πx:O. nat` 不合法 |

kernel 也完全照这个分层来写：
- **构造器**：Rocq 的 OCaml 构造子 `Prod(...)`（以及辅助函数 `mkProd`），Lean 的 `Expr.forallE`，都可以直接拼出 `Πx:O. nat`，不会报错。
- **检查函数**：只有交给 kernel 检查时，`Prod` 分支或 `infer_pi` 才会发现问题并拒绝。

## 项构造器，项是否合法，构造出的项的类型

|                      | 类型论                                        | Rocq                                                          | Lean                                              |
| -------------------- | ------------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------- |
| **构造器**：拼出项          | Π                                          | `constr` 类型的 OCaml 构造子 `Prod`                                 | `Expr` 归纳类型的构造子 `forallE`（C++ 里叫 `expr_kind::Pi`） |
| **形成规则**：判断拼出来的项是否合法 | `A : s₁`，且 `x:A ⊢ B : s₂`，则 `Πx:A. B : s₃` | `execute` 里的 `Prod` 分支，加上 `type_of_product`/`sort_of_product` | `infer_pi`                                        |
| **结论**：合法的 Π 项是一个类型  | 它的类型是 Sort `s₃`                            | 返回 `mkSort s`                                                 | 返回 `mk_sort(r)`                                   |


- 在 kernel 里，第 2 行和第 3 行是同一个函数一次完成的。Prod 分支和 infer_pi 一边检查一边算类型：能算出类型（某个 Sort），就说明合法，并且把这个类型返回；算不出来，就直接报错。类型论里也是这样，"合法"的意思就是"能推出 Πx:A. B : s₃ 这个判断"。
#### λ 也是同一个模式

| | 类型论 | Rocq | Lean |
|---|---|---|---|
| 构造器 | λ | `Lambda` | `Expr.lam` |
| 引入规则 | 若 `x:A ⊢ t : B`，则 `λx:A. t : Πx:A. B` | `Lambda` 分支，加上 `type_of_abstraction` | `infer_lambda` |
| 结论 | 合法的 λ 项是一个**值**，类型是 Π | 返回 `mkProd(x, A, B)` | 返回 `mk_pi(...)` |

两者的区别在于：Π 构造出来的是**类型**，λ 构造出来的是**值**，而 λ 的检查结果正是一个 Π。
