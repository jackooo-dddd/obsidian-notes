## CoC 核心语法的五种形式

```text
项 t, u, A, B ::= x           变量，x 代指任意变量名
               | s           Sort（例如 Prop、不同层级的 Type）
               | Πx:A. B     依赖函数类型，其中 A 和 B 本身又是项
               | λx:A. t     函数抽象，其中 A 和 t 本身又是项
               | t u         函数应用
```

项的定义里又用到了“项”本身。所以大的项由小的项通过组合形式组成，小的项又由更小的项组成，一直拆到最底层为止。

**定义为什么是递归的**：在 `Πx:A. B` 里，`A`、`B` 必须是项。

### 为什么不会无限循环：有叶子

五种形式里，`x`（变量）和 `s`（Sort）不需要任何子项，它们就是最小的项，也就是树的叶子。CIC 里还多了几种叶子：全局引用 `nat`、`le`、`S`（`Ind`、`Construct`、`Const`）。所以每个项都是有限的：从叶子开始，经过有限次 Π、λ、App 的组合，就能拼出来。

## 在 lt 的 body 里

### 从下往上读，就是“拼”

```text
S、n                        叶子
S n                         ← 用 App 把 S 和 n 拼起来
le (S n)                    ← 再用 App 把 le 和 S n 拼起来
le (S n) m                  ← 再用 App 拼上 m
λm:nat. le (S n) m          ← 用 λ 包起来
λn:nat. λm:nat. le (S n) m  ← 再用 λ 包一层
```

### 从上往下读，就是“拆”

每一层只看根节点是哪种形式，把它拆成几个子项，再对每个子项做同样的事，直到叶子。树里每个节点连同它下面的部分，都是一个完整的项。比如 `S n`、`le (S n) m` 都是项，只是比整个 body 小。

## 这对 kernel 和翻译器意味着什么

正因为项是递归定义的，处理项的程序也都是递归写的：只需要为每种形式写一条处理规则，然后对子项调用自己。

- **kernel 类型检查**：遇到 `Prod`，先递归检查 `A` 和 `B`，再算出 Sort；遇到 `Lambda`，先检查 `A`，再递归检查 body。
- **翻译器**：遇到 `Prod(x, A, B)`，先递归翻译 `A` 和 `B`，再组装成 `forallE x ⟦A⟧ ⟦B⟧`；遇到叶子 `rel i`，直接换成 `bvar i`。

“子项本身就是这样一层层翻译过来的，所以 `⟦A⟧` 在 Lean 里也是类型”，用的就是这个结构：先保证小的项翻译正确，大的项就跟着正确。这在数学上叫**结构归纳**。
