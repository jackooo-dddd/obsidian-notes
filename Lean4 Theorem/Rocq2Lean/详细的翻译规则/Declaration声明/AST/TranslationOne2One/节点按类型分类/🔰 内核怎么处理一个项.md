### 1. 内核只回答一个问题
内核拿到一个项，只回答：

> **这个项合不合法？如果合法，它的类型是什么？**

这两个问题其实是一回事：
- 能推出类型，项就合法，同时得到了它的类型；
- 推不出来，比如变量查不到、参数类型对不上，内核就报错，项不合法。

**类型推断：每个子项都要做**

kernel 检查一个项时，会从叶子往上递归推出每个子项的类型。Π、λ、app、叶子都一样。所以第一条"Γ ⊢ t : A ⇒ ⟦Γ⟧ ⊢ ⟦t⟧ : ⟦A⟧"要对每个子项成立，结构归纳也正是沿着这条走。

**定义等价：只在需要比较两个东西时才做**
Rocq 调 `conv_leq`、Lean 调 `is_def_eq`，只发生在几个固定的位置：

|位置|比较什么|
|---|---|
|app 节点 `f a`|`a` 的类型 vs `f` 的参数类型|
|整条声明|body 推出来的类型 vs 声明写的类型|
|let|值的类型 vs 标注的类型|

Π 节点和 λ 节点本身不做这种比较。
### 2. 输入和输出

| |内容|
|---|---|
|输入|**环境**：已经定义好的全局声明，如 `nat`、`le`、`S`<br>**上下文**：当前位置已经引入的局部变量，如外层 `fun n =>` 引入的 n<br>**一个项**|
|输出|这个项的类型，或者报错|

### 3. 两个核心过程
内核内部靠两个过程完成这件事：

|过程|做什么|Rocq|Lean|
|---|---|---|---|
|**推类型**|给一个项，推出它的类型|`execute`（`kernel/typeops.ml`）|`infer_type_core`（`src/kernel/type_checker.cpp`）|
|**判相等**|给两个类型，判断它们是否相等|`conv` / `conv_leq`（`kernel/conversion.ml`）|`is_def_eq`|

两个过程互相配合。推类型时经常要判相等，比如调用函数时要检查"参数的类型是否等于函数要求的类型"。
### 4. 推类型的做法：看节点种类，递归处理
推类型的函数先看**最外层是哪种节点**，按这种节点的规则处理；遇到子项，就对子项再调用自己。两边的结构相同：

```ocaml
(* Rocq：execute_aux *)
match kind cstr with
| Rel n               -> ...   (* 局部变量 *)
| Const c             -> ...   (* 全局常量 *)
| Sort s              -> ...   (* 层 *)
| Prod (name,c1,c2)   -> ...   (* 函数类型 *)
| Lambda (name,c1,c2) -> ...   (* 函数 *)
| App (f,args)        -> ...   (* 函数调用 *)
```

```cpp
// Lean：infer_type_core
switch (e.kind()) {
case expr_kind::FVar:   r = infer_fvar(e);     break;  // 局部变量
case expr_kind::Const:  r = infer_constant(e); break;  // 全局常量
case expr_kind::Sort:   r = mk_sort(...);      break;  // 层
case expr_kind::Pi:     r = infer_pi(e);       break;  // 函数类型
case expr_kind::Lambda: r = infer_lambda(e);   break;  // 函数
case expr_kind::App:    r = infer_app(e);      break;  // 函数调用
```

### 5. 处理节点时用到的四个工具

|工具|作用|Rocq|Lean|
|---|---|---|---|
|上下文|进入函数类型或函数时加入新变量；遇到变量时查它的类型|`push_rel`、`lookup_rel`|`mk_local_decl`、`find_local_decl`|
|环境|查全局声明的类型和定义|`lookup_constant` 等|`env().get`|
|化简|把类型计算到能看清最外层，比如"是不是一个层""是不是函数类型"|`whd_all`、`whd_stack`|`whnf`|
|判相等|比较两个类型是否相等|`conv_leq`|`is_def_eq`|

### 6. 检查一个完整的声明
对一条定义，两边内核都做三步：

|步骤|Rocq（`infer_definition`）|Lean（`add_definition`）|
|---|---|---|
|① 声明的类型确实是一个类型|`infer_type env t`|`check_constant_val`（内部 `ensure_sort`）|
|② 推出定义体的类型|`infer_hconstr env hbody`|`checker.check(value)`|
|③ ② 的结果和声明的类型相等|`check_cast … DEFAULTcast`（用 `conv_leq`）|`is_def_eq(val_type, type)`|

**小结：两边内核处理项的方式相同。** 都是"推类型 + 判相等"，按节点种类递归处理，用同样的四个工具。剩下要确认的，是每种节点的具体处理步骤是否也相同。
