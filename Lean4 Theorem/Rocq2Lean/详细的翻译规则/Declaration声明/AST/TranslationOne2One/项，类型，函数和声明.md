**项是表达式；类型和函数是按类型关系识别的项；声明是环境中保存这些项及相关信息的记录。** 这四个概念不在同一个层次上，不能简单地并列成四种 AST 节点。

| 概念                  | 核心含义               | 例子                                    |
| ------------------- | ------------------ | ------------------------------------- |
| **项（term）**         | 用 kernel 节点组成的表达式  | `3`、`nat`、`fun n => S n`、`nat -> nat` |
| **类型（type）**        | 类型为某个 Sort 的项      | `nat`、`nat -> nat`、`3 <= 5`           |
| **函数（function）**    | 类型可归约为 Prod 的项     | `S`、`Nat.add`、`fun n => S n`          |
| **声明（declaration）** | 环境中的记录，保存类型、定义体等信息 | `Definition lt ...` 产生的常量声明           |

下文用 `E` 表示全局环境，用 `Γ` 表示局部上下文。类型判断写作 `E; Γ ⊢ t : T`：在这些声明和局部假设下，项 `t` 的类型是 `T`。

## 一、项：kernel 操作的表达式

### 1. 项在kernel里面 = 节点 + 它的输入

项由 `Rel`、`Const`、`Ind`、`Construct`、`Sort`、`Prod`、`Lambda`、`LetIn`、`App`、`Case`、`Fix`、`CoFix`、`Proj`、`Cast`、原语字面量等节点构成。

每个项的根部是一个节点（构造子），节点带着若干输入：

- **输入本身又是项**：比如 `Prod(n, nat, B)` 里的 `nat` 和 `B`。
- **输入是原子数据，不是项**：比如 `Rel 1` 里的编号 `1`、`Const lt` 里的名字 `lt`、参数名 `n`。

正因为输入还可以是项，项才会形成一棵树：根是一个节点，往下一层层分叉，直到 `Rel`、`Const`、`Sort` 这些叶子为止。类型论（BNF）、Rocq（`constr`）、Lean（`Expr`）都是这样。
### 2. 类型、命题和证明也都是项

左列是项的源码或人可读的打印形式，右列是同一个项的节点树。**节点一直都在，只是人可读的写法没有把它们显式画出来。**

| 项的源码           | 项本身（节点树）                                                                  | 所扮演的角色         |
| -------------- | ------------------------------------------------------------------------- | -------------- |
| `O`            | `Construct O`                                                             | 自然数值           |
| `S O`          | `App(Construct S, [Construct O])`                                         | 自然数值           |
| `3`            | `App(Construct S, [App(Construct S, [App(Construct S, [Construct O])])])` | 自然数值；`3` 是数字记号 |
| `fun n => S n` | `Lambda(n, Ind nat, App(Construct S, [Rel 0]))`                           | 函数             |
| `nat`          | `Ind nat`                                                                 | 类型             |
| `nat -> nat`   | `Prod(_, Ind nat, Ind nat)`                                               | 函数类型           |
| `3 <= 5`       | `App(Ind le, [〈3 的节点树〉, 〈5 的节点树〉])`                                       | 命题，也是证明的类型     |
| `le_n 3`       | `App(Construct le_n, [〈3 的节点树〉])`                                         | `3 <= 3` 的证明   |
| `Prop`         | `Sort Prop`                                                               | Sort，即类型所属的层级  |
| `Set`          | `Sort Set`                                                                | Sort，即类型所属的层级  |
| `Type@{u}`     | `Sort Type@{u}`                                                           | Sort，即类型所属的层级  |


#### 什么时候使用哪种写法

| 场景                          | 使用的写法                          | 原因                                  |
| --------------------------- | ------------------------------ | ----------------------------------- |
| 写 Rocq / Lean 代码、做证明、讨论数学含义 | 人可读的写法                         | 关注表达式的意思，显式节点太冗长                    |
| 讲类型论规则                      | `Πx:A. B`、`λx:A. t`、`t u`      | 用简洁的符号表达项的结构                        |
| 研究 kernel、写翻译器、看导出的 IR、调试   | `Prod(...)`、`App(...)`、`Rel i` | 关注节点结构、de Bruijn 编号，以及应用是多参数还是单参数形式 |

## 二、类型：一种项所扮演的角色

### 怎样判断一个项是不是类型

**如果 `T` 的类型可归为某个 Sort，就可以把 `T` 当作类型。** 常见 Sort 包括 `Prop`、`Set`、`Type@{u}`

```text
t : T       表示 t 的类型是 T
T : s       表示 T 本身也是项，而且它的类型是 Sort s
```

例如：

```text
3        : nat
nat      : Set
Set      : Type@{Set+1}

3 <= 5   : Prop
Prop     : Type@{Set+1}

Type@{u} : Type@{u+1}
```

- `nat` 是类型，因为 `nat : Set`。
- `3 <= 5` 是命题，也是类型，因为 `3 <= 5 : Prop`；它的元素就是该命题的证明。
- `3` 不是类型，因为 `3 : nat`，而 `nat` 不能归约成 Sort。

## 三、函数：按类型识别，而不是按外形识别

### 1. 函数类型由 Prod 表示

| 源码 | 项本身（节点形式） |
| --- | --- |
| `forall (x : A), B` | `Prod(x, A, B)` |

它要求：
1. 在当前上下文中，`A` 是类型。
2. 把 `x : A` 加入上下文后，`B` 也是类型。
3. 整个 Prod 所在的 Sort 由相应的 universe 规则决定。

`B` 可以依赖输入 `x`；如果不依赖，就可以写成普通箭头 `A -> B`。

### 2. 类型是函数类型的项，就是函数
如果 `f` 的类型可归约为 `Prod(x, A, B)`，就可以把 `f` 应用于参数。给定 `a : A`，得到：
```text
f a : B[x := a]
```
其中 `B[x := a]` 表示把输出类型中的 `x` 替换成实参 `a`。

**Lambda 是构造函数的方式，不是识别所有函数的唯一外形。**

| 项源码（人可读）                     | 项（节点 + 输入）                                      | 类型                  | 最外层节点       | 是函数吗        |
| ---------------------------- | ----------------------------------------------- | ------------------- | ----------- | ----------- |
| `fun n => S n`               | `Lambda(n, Ind nat, App(Construct S, [Rel 0]))` | `nat -> nat`        | `Lambda`    | 是           |
| `S`                          | `Construct S`                                   | `nat -> nat`        | `Construct` | 是           |
| `Nat.add`                    | `Const Nat.add`                                 | `nat -> nat -> nat` | `Const`     | 是           |
| `Nat.add 2`                  | `App(Const Nat.add, [〈2 的节点树〉])`                | `nat -> nat`        | `App`，部分应用  | 是           |
| 局部变量 `f`，假设 `f : nat -> nat` | `Rel i`（`i` 为 `f` 的绑定索引）                        | `nat -> nat`        | `Rel`（绑定变量） | 是           |
| `Nat.add 2 3`                | `App(Const Nat.add, [〈2 的节点树〉, 〈3 的节点树〉])`      | `nat`               | `App`       | 不是函数，是自然数项  |
| `nat -> nat`                 | `Prod(_, Ind nat, Ind nat)`                     | `Set`               | `Prod`      | 不是函数，是函数的类型 |


相关说明：[[⚠️ Prod 和 Lambda 包装 以及为什么要有 Prod 和 Lam]]。

### 3. 函数也可以接收类型、返回类型或返回证明

| 例子 | 类型 | 含义 |
| --- | --- | --- |
| `lt` | `nat -> nat -> Prop` | 返回命题的函数，即谓词 |
| `fun (A : Type) (x : A) => x` | `forall A : Type, A -> A` | 接收类型 `A`，再接收一个 `A` 的元素 |
| `fun (b : bool) => if b then nat else bool` | `bool -> Set` | 返回类型的函数 |
| 一个 `le_pred` 的证明项 | `forall n m, n <= m -> pred n <= pred m` | 接收 `n`、`m` 和一个证明，再返回另一个证明 |


最后一行体现了 Curry–Howard 对应：全称命题和蕴含的证明可以是函数。并非所有证明都是函数；仍要看它的类型是否是 Prod。

## 四、声明：环境中保存项的记录

### 1. 声明不是项，引用声明的表达式才是项

声明为类型、值或证明等对象提供全局名字，并保存后续类型检查需要的信息。别的项通过 `Const`、`Ind`、`Construct` 等节点引用相应对象。

```text
全局环境中的声明记录             表达式中的引用项

lt 的常量声明          ← 查找 →  Const lt
le 的归纳块            ← 查找 →  Ind le
同一归纳块中的构造子信息 ← 查找 →  Construct le_n
```

- **`Const lt` 的类型是函数类型**：
  - 源码形式：`forall n m : nat, Prop`。
  - 节点形式：`Prod(n, nat, Prod(m, nat, Prop))`。
  - 打印形式：`nat -> nat -> Prop`。

  kernel 给 `Const lt` 定类型时，直接查声明中保存的 `const_type`，不需要重新检查 body。

- **所以 `Const lt` 是函数，可以被应用**：类型是 Prod 的项就是函数。例如，`App(Const lt, [2; 5])` 的类型是 `Prop`，它就是命题 `lt 2 5`。

### 2. 常量声明 constant_body

常量声明的关键字段可以简化为：

```text
constant_body {
  const_type      : 项                 // 常量的类型
  const_body      : 定义体状态           // 透明、不透明、无 body 等
  const_universes : universe 信息
  ...
}
```

常见 body 状态如下。`OpaqueDef` 保存的是不透明证明的引用等信息，不必理解成直接内嵌一个普通项。

| body 状态 | 含义 | 常见来源 | 能否按普通透明定义展开 |
| --- | --- | --- | --- |
| `Def t` | 有透明定义体 | `Definition`、`Fixpoint`、以 `Defined` 结束的证明 | 可以，取决于透明性设置 |
| `OpaqueDef ...` | 有不透明定义体 | 以 `Qed` 结束的证明 | 不按透明定义展开 |
| `Undef ...` | 全局假设，没有定义体 | `Axiom`、`Parameter` | 无 body 可展开 |
| `Primitive ...` | 原语操作 | 原语声明 | 按 kernel 的内置计算规则处理 |


`Definition`、`Fixpoint`、`Theorem`、`Lemma`、`Axiom` 都可以产生常量声明。它们不是五种互不相干的 kernel 项节点；尤其是，**定理的证明本身仍然是项**。

| 名字 | 源码示意 | const_type | const_body 示意 |
| --- | --- | --- | --- |
| `zero` | `Definition zero := 0.` | `nat` | `Def O` |
| `t` | `Definition t := nat.` | `Set` | `Def nat`，body 本身是类型 |
| `succ` | `Definition succ := S.` | `nat -> nat` | `Def S` |
| `lt` | `Definition lt (n m : nat) := S n <= m.` | `forall n m : nat, Prop` | `Def (fun n m => S n <= m)` |
| `add` | `Fixpoint add ...` | `nat -> nat -> nat` | `Def (fix add ...)` |
| `le_pred` | `Theorem le_pred ...`，以 `Qed` 结束 | `forall n m, n <= m -> pred n <= pred m` | 不透明证明 |

翻译器的 `transparent`、`opaque_present`、`assumption` 等 `body_state` 标签，是对声明状态的项目侧编码。若某个定理被标记为 `statement_only`，表示翻译器只处理它的类型，**不表示 Rocq 中的定理没有证明**。

### 3. 归纳类型声明 mutual_inductive_body

`Inductive`、`Record`、`CoInductive` 的核心数据保存在归纳块中；互归纳定义可以让一个块包含多个类型。

```text
mutual_inductive_body {
  mind_params_ctxt : 共享的参数上下文
  mind_packets    : 各个归纳类型的信息，包括
                      名字
                      arity（归纳类型的类型）
                      构造子的名字和类型
  ...
}
```

例如：

```coq
Inductive le (n : nat) : nat -> Prop :=
| le_n : le n n
| le_S : forall m : nat, le n m -> le n (S m).
```

归纳块提供 `le`、`le_n`、`le_S` 的信息：

- `le` 通过 `Ind` 引用。
- `le_n`、`le_S` 通过 `Construct` 引用。
- 构造子信息存放在块内，不是各自单独的 `constant_body`。

归纳命令还可能生成归纳原则等辅助常量，不能把“一个归纳块”理解成“这条源码命令绝不会另外产生常量声明”。

### 4. 怎样准确地说声明“有类型”

严格地说，声明不是类型判断中的项；“声明有类型”通常是指**它记录了对应引用项的类型**。

| 声明中保存的信息 | 引用项 | 引用项的类型 |
| --- | --- | --- |
| `lt` 的常量记录 | `Const lt` | 由 `const_type` 给出 |
| `le` 的归纳类型信息 | `Ind le` | `nat -> nat -> Prop` |
| `le_n` 的构造子信息 | `Construct le_n` | `forall n : nat, le n n` |


kernel 给 `Const lt` 推断类型时，会查声明中已记录的类型，**不需要每次重新验证整份 body 的类型正确性**。声明或证明体的合法性由相应的检查流程保证；在可转换性比较中，透明 body 仍可能被展开。



## 五、与 Lean 的对应关系

| 层面 | Rocq | Lean |
| --- | --- | --- |
| 项的表示 | `Constr.t` 等 | `Expr` |
| 函数类型 | `Prod` | `Expr.forallE` |
| 函数抽象 | `Lambda` | `Expr.lam` |
| 全局声明信息 | 常量记录、归纳块等 | `ConstantInfo` 的各个分支 |
| 构造子信息 | 保存在归纳块中，以 `Construct` 引用 | 有单独的 `ctorInfo`，以 `Expr.const` 引用 |
| 递归与消去 | 核心项中有 `Case`、`Fix` 等节点 | `Expr` 中没有对应的 `Case` / `Fix` 节点，通常通过 recursor 等表达 |

**Rocq 也有 recursor / induction principle 常量**，例如 `nat_ind`、`nat_rec`、`nat_rect`。区别不是“Rocq 没有 recursor”，而是：

- Rocq 的这些原则可以由 `Case`、`Fix` 等核心项表达，是普通常量，不是 Lean `recInfo` 那样的专门声明类别。
- Lean 的环境中有专门的 `recInfo`，kernel 依据 recursor 的规则处理相应计算。

参见 [Rocq 的归纳原则说明](https://rocq-prover.org/doc/V9.1.1/refman/language/core/inductive.html)、[Lean 的 Expr API](https://lean-lang.org/doc/api/Lean/Expr.html) 与 [ConstantInfo 定义](https://github.com/leanprover/lean4/blob/master/src/Lean/Declaration.lean)。

## 总结：先分清表达式与环境记录

| 概念 | 是项吗 | 判断依据 |
| --- | --- | --- |
| **项** | 是 | kernel 表达式的语法树；通过类型检查后才是合法项 |
| **类型** | 是 | 自己的类型可归约为 Sort |
| **函数** | 是 | 自己的类型可归约为 Prod，不要求最外层是 Lambda |
| **声明** | 不是 | 环境记录，保存项的类型、定义体或归纳结构等信息 |

**Prod 是构造函数类型的节点，Lambda 是构造函数的节点；声明则保存这些项，而不是代替这些项。**
