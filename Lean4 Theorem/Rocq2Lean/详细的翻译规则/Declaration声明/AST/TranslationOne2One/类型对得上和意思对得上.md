合法性和类型对得上，回答的是"Lean 认不认它，认成什么类型"；意思相同，回答的是"翻译出来的东西，是不是原来那个东西"。下面各给一张图。

一、合法性和类型对得上

问题： Rocq kernel 接受 t : T，翻译后 Lean kernel 是否接受 ⟦t⟧ : ⟦T⟧？

            Rocq kernel 检查
  Rocq:   t  ───────────────────────▶  合法，类型 T
          │                              │
        翻译 ⟦·⟧                       翻译 ⟦·⟧
          ▼                              ▼
  Lean:  ⟦t⟧ ──────────────────────▶  合法，类型 ⟦T⟧
            Lean kernel 检查

怎么论证：

两边 kernel 都按节点递归检查。
每种节点在两边套用的是同一条类型论规则：
Prod / forallE：A 是类型，加入 x，B 是类型，再算 Sort（sort_of_product 和 imax 换名后一致）；
Lambda / lam：A 是类型，加入 x，算出 body 的类型 B，结果是 Π 类型（mkProd 和 mk_pi）。
小项对得上，每一层规则也相同，所以大项也对得上（结构归纳）。

lt 的例子：

Rocq:  body 推出  nat → nat → Prop  ＝ 声明的 type   → 接受
Lean:  ⟦body⟧ 推出 nat → nat → Prop ＝ ⟦声明的 type⟧ → 接受

项目里由谁检查： Lean kernel，它独立重新推断每个翻译结果的类型（TRANSLATED_AND_CHECKED）。

它发现不了的问题：

fun n => n      : nat → nat
fun n => S n    : nat → nat     ← 类型一样，意思不同
二、意思相同

问题： ⟦t⟧ 是不是原来那个 t，只是换了一套写法？

图 A：逐节点对应（以 lt 的 body 为例）

  Rocq 的树                              Lean 的树
  Lambda(n, nat, ·)        ═══════▶      lam n nat ·
  └ Lambda(m, nat, ·)      ═══════▶      └ lam m nat ·
    └ App(Ind le, ·, ·)    ═══════▶        └ app (app le · ) ·
      ├ App(Construct S, ·)═══════▶          ├ app S ·
      │ └ rel 1            ═══════▶          │ └ bvar 1
      └ rel 0              ═══════▶          └ bvar 0

  每条 ═══▶ 都是"同一个类型论构造"：λ 对 λ，应用对应用，同一个变量对同一个变量，
  全局引用对"同一个声明翻译后的版本"

图 B：两边解释成同一个东西

  Rocq:   t   ──── 解释 ────▶   数学上的对象
          │                     （比如"n, m ↦ n+1 ≤ m 这个关系"）
        翻译 ⟦·⟧                    ║  同一个
          ▼                         ║
  Lean:  ⟦t⟧  ──── 解释 ────▶   数学上的对象

怎么论证：

每种节点意思相同：Prod/forallE 都是 Π，Lambda/lam 都是 λ，rel i/bvar i 指向同一个参数，Sort 按 I 换名，全局名指向已经翻译过的同一个声明。
组合性：一个项的意思只由子项的意思和根节点的组合方式决定。翻译只替换节点，不改变树的结构，所以整棵树的意思相同。
按依赖顺序推到全局：先 nat、le，再 lt，因为每个声明引用的东西都已经翻译过。

项目里由谁检查：

audit.py：逐项核对 Lean 项确实等于 ⟦源项⟧，也就是没有偷偷改结构（结果是 MATCH）；
round trip：保证导出的 IR 就是 Rocq kernel 里的那个项；
BOOTSTRAP = {}：nat 被翻成 Rocq.…nat，没有被换成 Lean 自己的 Nat。

它发现不了的问题： 结构对上了，Lean 也不一定接受。比如源码依赖 Rocq 的累积性（自动升层），逐节点翻译后 Lean 会拒绝，需要插入 PULift。

三、对比
	合法性和类型对得上	意思相同
回答的问题	Lean 接受吗？类型对吗？	是不是同一个东西？
比较的是	两边 kernel 给出的类型	两边的项本身（结构和每个节点）
论证依据	每种节点的规则步骤两边相同	每种节点的意思相同，再加上组合性
项目里的检查	Lean kernel	audit.py 和 round trip
单独用时漏掉的情况	类型对、意思错（n 被换成 S n）	结构对、Lean 不接受（缺 PULift）
已知的例外	Prop 自己的类型差一层（R2⁺）	Case/Fix → rec 不是逐节点对应，需要单独论证

两者合起来才完整： Lean 接受了，类型也对，而且翻译出来的正是原来那个东西。所以才能说，翻译后的声明和原声明是同一个声明。
