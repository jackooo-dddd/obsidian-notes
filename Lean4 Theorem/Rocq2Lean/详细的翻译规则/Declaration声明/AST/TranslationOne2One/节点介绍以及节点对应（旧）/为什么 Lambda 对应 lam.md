
#### 1. 回顾：类型和值
在类型论里，每个东西都有一个类型：
- **类型**说明"这是什么样的东西"，比如 `nat → nat`；
- **值**是属于这个类型的具体东西，比如 `fun n => n + 1`。

上一节讲的 Π 类型（`Prod`）负责写出"**给我任意 x : T，我就给你 B**"这种**类型**。

但光有类型还不够。写出 `nat → nat` 只是说"这里需要一个从 nat 到 nat 的函数"，还得有办法**真的造出一个这样的函数**。这就是 λ 的工作。
#### 2. 为什么需要 λ
λ 写作 `λ x : T, b`，意思是：

> **给我一个 x : T，我就算出 b 给你。**

它是造出 Π 类型的值的**唯一方式**。前面 Π 的三种读法，每一种都要靠 λ 才能给出具体的值：

|Π 类型（要求）|λ（满足要求的值）|读作|
|---|---|---|
|`nat → nat`|`fun n : nat => n + 1`|一个函数：输入 n，返回 n + 1|
|`forall n : nat, n + 0 = n`|`fun n : nat => (n + 0 = n 的证明)`|一个证明：对任意 n，给出对应的证明|
|`forall A : Type, A → A`|`fun (A : Type) (x : A) => x`|一个多态函数：对任意类型 A，原样返回|

没有 λ 会怎样：
- **写不出函数**：只能说"需要一个 nat → nat"，却没法给出一个；
- **证不了"对所有"**：要证 `forall n, …`，就得给出一个"接收任意 n、返回证明"的东西，这个东西就是 λ；
- **写不了多态**：没法写出"对任何类型都适用"的函数。

所以 **Π 和 λ 必须成对出现**：Π 写出要求，λ 满足要求。任何基于类型论、既要写程序又要写证明的语言，有了 Π 就必须有 λ。
#### 3. Rocq 和 Lean 都有它
因为两边都离不开 λ，它们各自在 AST 里设了一个节点来表示它：

| |Rocq|Lean|
|---|---|---|
|节点名|`Lambda`|`lam`|
|装的东西|变量名 x、类型 T、body b|变量名 x、类型 T、body b|
|规则|有了 x : T 时 b : B，那么 `λ x : T, b` 的类型就是 `Π x : T, B`|一样|
|计算|调用时把 x 换成实参：`(λ x, b) a` 化简为 `b[x := a]`|一样|

名字不同，但**表示的是同一个概念，遵守的是同一套规则**。
#### 4. 所以 Lambda 对应 lam
Rocq 里的 `Lambda` 说的是"给我一个 x : T，我就算出 b"。Lean 里说这句话的节点是 `lam`。所以：

Rocq:  Lambda(x, T, b)
Lean:  lam x T b

x 照抄，T 和 b 再分别翻译。

和 Prod 比，Lambda 更简单：它不需要处理"属于哪一层"的问题。λ 的类型直接就是对应的 Π，而 Π 的那一层已经在 `Prod` 的翻译里处理好了。

---

**一句话总结：** Π 说"需要什么样的函数"，λ 负责"造出这样的函数"。两边语言都有 Π，所以都必须有 λ。`Lambda` 和 `lam` 就是同一个东西在两边的名字。
