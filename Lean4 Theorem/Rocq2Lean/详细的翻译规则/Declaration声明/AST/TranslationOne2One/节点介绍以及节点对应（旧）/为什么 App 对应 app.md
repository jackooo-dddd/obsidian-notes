#### 1. 一句话
App 就是**调用**：把一个值交给一个函数，拿回结果。写作 `f a`。
#### 2. 先看清 f 的类型里有什么
函数 f 的类型是一个 Π 类型，前面讲过，写作 `Π x : T, B`。在 f 身上，它的三个部分是这样读的：

|部分|对 f 来说的意思|
|---|---|
|T|f **要求**输入的类型|
|B|f **返回**的类型（可能依赖输入 x）|
|x|输入的名字，B 里可能用到它|

例子：

|f|f 的类型|T（要什么）|B（给什么）|
|---|---|---|---|
|`S`|`nat → nat`|`nat`|`nat`|
|`plus_n_O`|`forall n : nat, n = n + 0`|`nat`|`n = n + 0`|

#### 3. 类型论里 App 的规则
类型论对 App 的规定只有一条：

如果  f 的类型是 Π x : T, B
并且  a 的类型是 T
那么  f a 的类型是 B，其中 x 换成 a

拆开说：
1. **f 必须是函数**，它的类型得是一个 Π；
2. **a 必须符合 f 的要求**，a 的类型必须是 T；
3. **结果的类型**是 B，并且把 B 里的 x 换成实际传进去的 a。

所以，"检查 a 的类型是不是 T"不是翻译器自己加的，而是**类型论本身对 App 的要求**，也就是这条规则的第 2 点。
#### 4. 用例子走一遍
**例 1：`S 3`**
- f = `S`，类型是 `nat → nat`，所以 T = `nat`，B = `nat`
- a = `3`，类型是 `nat`，和 T 一致
- 结果 `S 3` 的类型是 `nat`

**例 2：`plus_n_O 3`**
- f = `plus_n_O`，类型是 `forall n : nat, n = n + 0`，所以 T = `nat`，B = `n = n + 0`
- a = `3`，类型是 `nat`，和 T 一致
- 结果的类型是 B 里的 n 换成 3，即 `3 = 3 + 0`

这正是"把定理用在 3 上"：得到一个关于 3 的具体结论。B 里的 x 换成 a 这一步，就是在这里起作用的。

**例 3：`S true`**
- f = `S`，要求 T = `nat`
- a = `true`，类型是 `bool`，和 T 不一致
- 类型检查报错
#### 5. 这个检查为什么重要
计算机检查程序和证明对不对，靠的就是这类规则。App 的检查保证了：
- 程序不会把 `bool` 传给要 `nat` 的函数；
- 证明不会把定理用在不符合条件的东西上。

只要每一步 App 都通过检查，整个证明就是对的。
#### 6. 在类型论里的位置
对 Π 类型来说，三个节点各管一件事：

|节点|做什么|规则|
|---|---|---|
|Π（`Prod`）|写出函数类型|T 是类型，B 是类型，那么 `Π x : T, B` 是类型|
|λ（`Lambda`）|造出函数|有了 x : T 时 b : B，那么 `λ x : T, b : Π x : T, B`|
|App（`App`）|使用函数|`f : Π x : T, B`，且 `a : T`，那么 `f a : B[x := a]`|

在类型论的术语里：Π 是**形成**，λ 是**引入**，App 是**消去**，也就是把一个函数"用掉"，得到它的结果。
#### 7. Rocq 和 Lean 都有它
两边都有 Π 和 λ，所以都需要 App；两边的 App 规则也完全一样，就是上面第 3 节那条。

唯一的形式差别：
- Rocq 的 `App` 一次装多个参数：`App(f, [a₁, a₂])`；
- Lean 的 `app` 一次装一个参数：`app (app f a₁) a₂`。

翻译时把多个参数一层层套起来即可，意思不变。
#### 8. 两边检查"a 的类型是不是 T"时有一点不同
两边都要求 a 的类型符合 T，但对"符合"的宽松程度不一样：

| |Rocq|Lean|
|---|---|---|
|a 的类型正好是 T|||
|a 在比 T **更小的一层**（比如 T 要求 `Type`，a 是一个命题）| 允许，小的可以当大的用| 不允许，必须正好一致|

所以在少数情况下，Rocq 里能通过的调用，直接搬到 Lean 会报错。翻译器的处理办法是在 a 外面加一层显式的"提升"（`PULift`），把 a 变成 T 要求的那一层。绝大多数 App 不会遇到这个问题，直接一一对应。
