## 总览：项构造器负责拼项，规则负责判断与计算
**Π、λ、应用是项构造方式；形成、引入、消去、计算是规则。** 两者有关联，但不是同一种东西。
### 1. 先区分三类概念

| 类别 | 作用 | 函数家族里的成员 |
| --- | --- | --- |
| **项构造器 / 节点** | 描述项的结构，用来拼出项 | Π：`Prod` / `forallE`；λ：`Lambda` / `lam`；应用：`App` / `app` |
| **类型规则** | 判断这些项何时类型正确，并给出它们的类型 | 形成、引入、消去 |
| **计算规则** | 规定项怎样化简，以及化简前后的项为什么定义相等 | β |


### 2. 四条规则分别管什么

**规则针对的是具体的项，不是构造器的名字本身。** 例如，形成规则不是检查“`Prod` 这个构造器是否合法”，而是检查用它组成的整个项 `Prod(x, A, B)`：参数类型 `A` 和值域 `B` 是否满足要求，整个项的类型是什么。

要分清三个层次：

- **构造器**：例如 `Prod`，规定这种节点有哪些输入。
- **具体的项**：例如 `Prod(x, A, B)`，已经填入了具体输入，是一棵项树。
- **规则**：不仅判断项是否合法、类型是什么，也说明怎样构造或使用这些项，以及使用后怎样化简。

| 规则 | 描述什么 |
| --- | --- |
| **形成（Π）** | `Πx:A. B` 是否是合法的函数类型，以及它属于哪个 Sort |
| **引入（λ）** | 怎样用 `λx:A. t` 构造函数，以及这个函数的类型 `Πx:A. B` |
| **消去（应用）** | 怎样使用已有的函数：给 `f` 一个合适的实参 `a`，得到 `f a : B[x:=a]` |
| **计算（β）** | 使用 λ 函数后具体算出什么：`(λx:A. t) a` 化简成 `t[x:=a]` |

所以：

- **前三条是类型规则**：既说明相应的项何时合法、类型是什么，也给出构造和使用的方法。例如，消去规则不只是检查 `f a`，也告诉我们：已有 `f : Πx:A. B` 和 `a : A`，就可以把 `a` 传给 `f`，得到 `B[x:=a]` 类型的结果。
- **第四条是计算规则**：它不是再判断一次类型是否合法，而是说明“先用 λ 构造函数，再应用它”时，具体怎样代入、算出什么；化简前后的项定义相等。

#### 每条规则具体检查或化简哪个项

| 规则        | 针对的完整项        | 怎样识别它                   | 检查或处理哪些部分                                                    | 得到什么                                 |
| --------- | ------------- | ----------------------- | ------------------------------------------------------------ | ------------------------------------ |
| **形成**    | `Πx:A. B`     | 根节点是 `Prod` / `forallE` | 检查 `A` 是类型；在加入 `x : A` 的上下文中检查 `B` 是类型，再按 universe 规则确定 Sort | 整个 Π 项的类型：`Πx:A. B : s₃`             |
| **引入**    | `λx:A. t`     | 根节点是 `Lambda` / `lam`   | 检查参数类型 `A`，在加入 `x : A` 的上下文中检查函数体 `t` 的类型 `B`，并保证相应 Π 类型合法   | 整个 λ 项的类型：`λx:A. t : Πx:A. B`        |
| **消去**    | `f a`         | 根节点是 `App` / `app`      | 检查函数部分 `f` 的类型是 `Πx:A. B`，并检查实参 `a : A`                      | 整个应用项的类型：`f a : B[x:=a]`             |
| **计算（β）** | `(λx:A. t) a` | 根节点是应用，而且函数部分是 λ        | 把实参 `a` 代入函数体 `t`，替换其中由这个 λ 绑定的 `x`                          | 化简结果：`(λx:A. t) a →β t[x:=a]`，两者定义相等 |

因此，**“看根节点”是为了选择规则；“检查输入和上下文”才是为了判断这个具体项是否类型正确。** 不能只看到一个 `Prod`、`Lambda` 或 `App` 节点，就认为它已经合法。
#### 消去与 β 针对的范围不同

- **消去规则针对一般的应用项 `f a`**：只要 `f` 的类型是函数类型，就可以检查这次应用；不要求 `f` 本身写成 λ。
- **β 规则针对应用项中的一种特定组合**：函数部分恰好是 λ，也就是 `App(Lambda(x, A, t), a)`，才可以进行这一步 β 归约。

β 没有自己的构造器或节点。它规定的是**一个应用项如何化简为另一个项**，不是再拼出一种新节点。

**简言之：形成、引入、消去为相应形状的具体项建立类型判断；β 则为“应用 λ”这种具体结构规定归约关系。**

### 3. kernel 中怎样体现这种区别

| 规则 | 涉及的节点：Rocq / Lean | 检查或计算逻辑：Rocq / Lean |
| --- | --- | --- |
| 形成 | `Prod` / `forallE` | `Prod` 检查分支 / `infer_pi` |
| 引入 | `Lambda` / `lam` | `Lambda` 检查分支 / `infer_lambda` |
| 消去 | `App` / `app` | `App` 检查分支 / `infer_app` |
| 计算 | `App` 与 `Lambda` / `app` 与 `lam` 的组合，没有独立的 β 节点 | 归约与比较逻辑，如 `conversion.ml` / `whnf`、`is_def_eq` |

**一句话：构造器决定“这个项长什么样”；类型规则决定“这个项是否合法、类型是什么”；计算规则决定“这个项怎样化简”。**

整篇都用这两个例子贯穿：

```
加二：  λn:nat. S (S n)          （普通函数）
自反：  λn:nat. le_n n           （依赖函数：le_n n 是 n ≤ n 的证明）
```


阅读下面的规则时记住：横线**上面**是前提，**下面**是结论；`Γ ⊢ t : T` 读作"在已知变量 Γ 下，t 的类型是 T"。

## 一、形成：怎样造出一个"函数类型"
### 规则

```
Γ ⊢ A : s₁        Γ, x:A ⊢ B : s₂
───────────────────────────────────   (Π-形成)
Γ ⊢ Πx:A. B : s₃
```

读法：
1. A 是一个类型（它的类型是某个 Sort `s₁`），作为**输入类型**。
2. 假设手里有一个 `x : A`，在这个前提下，B 也是一个类型，作为**输出类型**。B 里可以出现 x。
3. 那么 `Πx:A. B` 就是一个合法的类型。它自己也有类型，是一个 Sort `s₃`，由 s₁、s₂ 按 universe 规则算出。
### 例子
**`Πn:nat. nat`**（即 `nat → nat`），"加二"的类型：

| 步骤 | 检查 | 结果 |
|---|---|---|
| 1 | `nat` 是类型吗？ | 是，`nat : Set` |
| 2 | 假设 `n : nat`，`nat` 是类型吗？ | 是，`nat : Set` |
| 3 | 结论 | `Πn:nat. nat : Set` |

**`Πn:nat. n ≤ n`**，"自反"的类型：

| 步骤 | 检查 | 结果 |
|---|---|---|
| 1 | `nat` 是类型吗？ | 是 |
| 2 | 假设 `n : nat`，`n ≤ n` 是类型吗？ | 是，`n ≤ n : Prop`。这里用到了 n，这就是"依赖" |
| 3 | 结论 | `Πn:nat. n ≤ n : Prop` |

### 反例（拼得出来，但不合法）

| 项 | 卡在哪一步 | 原因 |
|---|---|---|
| `Πx:O. nat` | 第 1 步 | `O : nat`，`O` 是一个数，不是类型 |
| `Πn:nat. S n` | 第 2 步 | `S n : nat`，`S n` 是一个数，不是类型 |

### 要点
形成规则**不会造出任何函数**。它造出的只是一个**类型**，相当于一份规格说明："给我一个 A 里的 x，我还你一个 B（可能依赖 x）里的东西。"

## 二、引入：怎样造出一个具体的函数
### 规则

```
Γ, x:A ⊢ t : B
─────────────────────────   (λ-引入)
Γ ⊢ λx:A. t : Πx:A. B
```

读法：
1. 假设手里有一个 `x : A`，在这个前提下写出函数体 t，并算出它的类型是 B。
2. 那么 `λx:A. t` 就是一个函数，它的类型是 `Πx:A. B`。

结论里的类型，正是上一节形成规则造出的那种类型。也就是说，**λ 造出的函数，就是 Π 类型的值**。
### 例子
**加二**：`λn:nat. S (S n)`

| 步骤 | 内容 |
|---|---|
| 1 | 假设 `n : nat` |
| 2 | 算出函数体的类型：`S n : nat`，所以 `S (S n) : nat`，B 就是 `nat` |
| 3 | 结论：`λn:nat. S (S n) : Πn:nat. nat` |

**自反**：`λn:nat. le_n n`

| 步骤 | 内容 |
|---|---|
| 1 | 假设 `n : nat` |
| 2 | 算出函数体的类型：`le_n n : n ≤ n`，B 就是 `n ≤ n`，里面带着变量 n |
| 3 | 结论：`λn:nat. le_n n : Πn:nat. n ≤ n` |

注意第 2 步：此时 n **只是一个变量**，并不知道它具体是几。所以 B 记录的是"对**每一个** n，结果的类型是 `n ≤ n`"。用逻辑的话说，这就证明了"对所有 n，都有 n ≤ n"。
### 反例
`λn:nat. S true`：第 2 步就失败了，因为 `S` 要一个 nat，给的却是 bool，函数体没有类型，所以整个 λ 不合法。
### 要点
引入规则造出的是一个**值**，即具体的函数。它的类型不是凭空给的，而是**从函数体的类型构造出来的**。

## 三、消去：怎样使用一个函数
### 规则

```
Γ ⊢ f : Πx:A. B        Γ ⊢ a : A
───────────────────────────────────   (应用)
Γ ⊢ f a : B[x:=a]
```

读法：
1. f 的类型是一个 Π，也就是说 f 是一个函数。
2. a 的类型正好是输入类型 A。
3. 那么 `f a` 的类型是 B，并且要把 B 里的 x 换成 a。
### 例子
**用加二**：`(λn:nat. S (S n)) 3`

| 步骤 | 检查 | 结果 |
|---|---|---|
| 1 | f 的类型 | `Πn:nat. nat` |
| 2 | `3 : nat` 吗？ | 是 |
| 3 | 结论 | `nat[n:=3]`，也就是 `nat` |

**用自反**：`(λn:nat. le_n n) 3`

| 步骤 | 检查 | 结果 |
|---|---|---|
| 1 | f 的类型 | `Πn:nat. n ≤ n` |
| 2 | `3 : nat` 吗？ | 是 |
| 3 | 结论 | `(n ≤ n)[n:=3]`，也就是 **`3 ≤ 3`** |

第二个例子显示了 `B[x:=a]` 的作用：**依赖就是在这一步兑现的**。传 3 得到 `3 ≤ 3` 的证明，传 5 就得到 `5 ≤ 5` 的证明。
### 反例
`(λn:nat. S (S n)) true`：第 2 步失败，`true : bool`，不是 `nat`。
### 要点：消去不关心 f 是怎么造出来的
f 只要类型是 Π 就行，**不一定**是 λ：

```
f : nat → nat 是上下文里的一个变量（不知道它具体是什么函数）
⊢ f 3 : nat                         ← 合法
```

消去规则只回答"`f a` 是什么**类型**"，并不负责把它算出来。在这个例子里，f 是什么都不知道，`f 3` 也就**算不动**，但它依然是一个类型正确的项。

## 四、计算：消去碰到引入时，怎样化简
### 规则

```
(λx:A. t) a   ≡   t[x:=a]          (β 归约)
```

读法：如果被使用的函数**恰好就是一个 λ**，就把实际参数 a 代进函数体 t 里，替换掉 x。
### 例子

```
(λn:nat. S (S n)) 3   →β   S (S 3)   就是 5
(λn:nat. le_n n) 3    →β   le_n 3    就是 3 ≤ 3 的一个具体证明
```

### 什么时候能算，什么时候不能

| 项 | 能用 β 吗 | 原因 |
|---|---|---|
| `(λn. S (S n)) 3` | 能 | 函数位置上正好是 λ |
| `f 3`（f 是上下文里的变量） | **不能** | 不知道 f 是不是 λ，算不动 |
| `add2 3`（add2 是一个已定义的常量） | 先 δ 展开，再 β | 先把 `add2` 换成它的 body `λn. S (S n)`，然后就能 β 了 |

这正是"消去碰到引入"的含义：**只有当用函数的人（App）碰到造函数的人（λ）时，计算才会发生。**
### 计算不会改变类型
把消去和引入两条规则对照一下：

```
(λn:nat. le_n n) 3   : 3 ≤ 3      （由消去规则得出）
le_n 3               : 3 ≤ 3      （由 le_n 的类型得出）
```

算之前和算之后，类型完全一样。这个性质叫**类型保持**（subject reduction）。正是有了它，kernel 才可以放心地"先算到底再比较"。
### 为什么需要计算
kernel 判断两个类型是否相等时要用到计算。比如要证明 `(λn. S (S n)) 3 = 5`，只需要给出 `eq_refl 5`：kernel 用 β 把左边算成 `5`，发现两边一样，就会接受。

## 总结：四条规则怎样连成一圈

```
       形成（Π）                     引入（λ）
  "什么算函数类型"   ──类型来自──  "怎样造一个函数"
  Πx:A. B : Sort                  λx:A. t : Πx:A. B
          │                              │
          │ 要求 f 的类型是 Π              │ f 恰好是 λ 时
          ▼                              ▼
       消去（应用）  ─────碰上───→     计算（β）
  "怎样用一个函数"                 "用刚造好的函数，结果是什么"
  f a : B[x:=a]                    (λx. t) a ≡ t[x:=a]
```

| 规则 | 造出什么 | 加二的例子 | 自反的例子 | Rocq / Lean |
|---|---|---|---|---|
| 形成 | 一个**类型** | `Πn:nat. nat` | `Πn:nat. n ≤ n` | `Prod`/`forallE`，检查函数 `Prod` 分支/`infer_pi` |
| 引入 | 一个**函数值** | `λn. S (S n)` | `λn. le_n n` | `Lambda`/`lam`，检查函数 `Lambda` 分支/`infer_lambda` |
| 消去 | 一个**应用项**，以及它的类型 | `(…) 3 : nat` | `(…) 3 : 3 ≤ 3` | `App`/`app`，检查函数 `App` 分支/`infer_app` |
| 计算 | **化简后的结果** | `S (S 3)` 就是 `5` | `le_n 3` | 归约和比较：`conversion.ml`/`whnf`、`is_def_eq` |
