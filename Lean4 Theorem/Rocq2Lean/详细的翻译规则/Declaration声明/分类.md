在 Rocq Kernel 内部，`Constant`、`Inductive`、`Constructor` 是不同的全局声明或引用类别。

例如 `nat` 本身是 Inductive，而 `O`、`S` 是 Constructor，不属于严格意义上的 Constant 声明，虽然它们也都有 Type。
## Constant 
Constant 是一个有全局名字的 Term（项），而这个 Term 拥有某个 Type， 可以把它理解为 某个 Type 的一个元素。
例如：
```
# x : nat 表示 x 是 nat 类型的一个元素。
Definition x : nat := 3.

# f 是函数类型的一个元素，而不是普通数字。
Definition add1 (n : nat) : nat := S n.

# Type 是一个 Sort（类型的类型层级）。
Definition MyType : Type := nat.

# 1 = 1 是一个命题（其类型为 Prop）。它的证明是这个命题类型的一个元素。
Theorem add_zero : forall n : nat, n + 0 = n.
Proof.
  ...
Qed.
```
从内核的角度，它们都属于 Constant 声明：

|Constant|Type|Body|
|---|---|---|
|`x`|`nat`|`3`|
|`add1`|`nat → nat`|`fun n => S n`|
|`MyType`|`Type`|`nat`|
|`add_zero`|`∀ n, n + 0 = n`|证明项|

特别注意 `MyType`：Constant 自己也可以表示一个类型，因为在 Rocq/Lean 的依赖类型系统中，类型本身也是可以被命名和传递的表达式。
## Inductive 
Inductive 声明一种新的归纳类型或类型族，包含其 Constructors；这个类型既可以表示数据，也可以表示命题。
```
Inductive nat : Set :=
| O : nat
| S : nat -> nat.
```
这里同时定义了：
- `nat`：新类型。
- `O`：构造一个 `nat`。
- `S`：接受一个 `nat`，构造另一个 `nat`。
Inductive 不只可以定义普通数据类型，也可以定义命题和归纳关系。例如：
```
Inductive myTrue : Prop :=
| intro : myTrue.
```
这里 `myTrue` 是一个命题，`intro` 是它的证明构造器。
- 并不是所有 Type 都通过 Inductive 定义。前面的 `MyType := nat` 就是通过 Constant 定义一个已有类型的别名。

对翻译流程比较重要的几类声明：

| Rocq 语法             | 在翻译器中的处理          | 特别之处                            |
| ------------------- | ----------------- | ------------------------------- |
| `Definition`        | Constant          | 翻译 Type + Body                  |
| `Theorem`、`Lemma`   | Constant          | 当前模式只翻译陈述，不翻译证明                 |
| `Axiom`、`Parameter` | 无 Body 的 Constant | 需要保留假设性质，不能当成已证明的定理             |
| `Inductive`         | Inductive Block   | 翻译构造器，生成 Recursors              |
| `Record`            | 特殊 Inductive      | 还涉及 Fields、Projections          |
| `Fixpoint`          | 通常是 Constant      | Body 包含 `Fix` AST，需要递归 Lowering |
| `CoFixpoint`        | 通常是 Constant      | Body 包含 `CoFix`，需处理余递归          |
| `CoInductive`       | 特殊归纳类声明           | Lean 没有完全对应的原生 CoInductive 声明   |


|层次|主要判断|决定什么|
|---|---|---|
|第一层：Declaration Structure|Constant / Inductive|如何构建 Lean Declaration|
|第二层：Declaration Semantics|Statement / Definition / Axiom；Template / Non-template|是否翻译 Body，怎样处理 Universe|
|第三层：Expression Structure|App / Lambda / Case / Fix / CoFix 等|`trans` 是否需要额外 Lowering|

- 第三层不是另一种 Declaration 分类，而是 `trans` 递归遍历 Body 或 Type 时遇到的表达式节点类型。
```
Rocq Declaration
       ↓
Exporter → AST + Metadata
       ↓
Declaration 分类
       ├── Constant
       │     ├── Statement（Type only）
       │     ├── Definition（Type + Body）
       │     │      ├── Type-valued
       │     │      └── Value-valued
       │     └── Axiom（无 Body）
       │
       └── Inductive Block
             ├── Template
             └── Non-template
       ↓
trans：AST → Lean Expr
       ├── 普通节点直接映射
       ├── Case → Recursor
       └── Fix → Recursion Lowering
       ↓
Universe Solving + Checks
       ↓
Lean Kernel
       ↓
对应性验证
```
- 真正实现中的分类会先于部分 `trans` 调用发生，而且 Universe Solving 和表达式翻译可能交替进行、多次重试。
