下面把三个概念放在一起整理。还是用 `count` 作为例子：

```coq
Definition count (A : Type@{197}) (l : list A) : nat := length l.
(* 关键字    名字  └──────── 参数 ────────┘   └返回类型┘    └ Body ┘ *)
```

### 1. 声明的类型（整个声明的类型）
**是什么：**`:=` 前面、名字后面的那一部分，也就是**参数加上冒号后的返回类型**，合起来读成一个 `∀`：

```text
count : ∀ (A : Type@{197}) (l : list A), nat
```

**意思**：这是 `count` 对外的“接口”，说明调用它需要提供什么、会得到什么：先给一个类型 `A`，再给一个 `A` 的列表 `l`，得到一个 `nat`。

**在哪里：**
- IR 中是 `ConstantDecl.type`；
- Lean 中是声明的 `type`：`∀ (A : Type u_197) (l : Rocq.list.{u_197} A), Rocq.nat`。

**和 Step 6 的关系**：⑤ 中说的“出现在类型里”，指的就是**这个**类型。调用者看得到它，所以出现在这里的 Level 要做成参数，让调用者能自由选择。
### 2. Body（声明的值）
**是什么**：源码中 `:=` 后面的那部分，`length l`。

但要注意，**存下来的 Body 不只是 `:=` 后面那一段**。冒号前的参数，在 Body 中会以 λ 的形式**再出现一次**：

```text
count := fun (A : Type@{197}) (l : list A) => length l
```

所以 IR 中的 Body 是 `lam A … (lam l … (app (const length []) [rel 1, rel 0]))`。参数 `A`、`l` 同时出现在类型（作为 `∀`）和 Body（作为 `fun`）中，这就是为什么 197 在类型和 Body 中都会出现。

**意思**：这是 `count` 的“实现”，即具体怎么算出结果。调用者只关心类型，不关心 Body 怎么写。

**在哪里：**
- IR 中是 `ConstantDecl.body`；
- Lean 中是声明的 `value`：`fun A l => Rocq.length.{u_197} A l`。
### 3. 某个子项的类型
**是什么**：声明的类型和 Body 都是由很多小的项（子项）组成的，**每一个子项都有它自己的类型**。

|子项|它的类型|
|---|---|
|`A`|`Type@{197}`|
|`l`|`list A`|
|`list A`|`Type@{197}`|
|`length`|`∀ (A : Type@{197}), list A → nat`（`length` 自己的声明类型）|
|`length l`|`nat`|
|`nat`|`Set`|

**意思**：子项的类型是**翻译和检查时内部用的**，不是接口。Lean 用 `inferType` 算它们，统一（Unification）就发生在这里：调用 `length l` 时，Lean 比较“`length` 要求的参数类型”和“`l` 实际的类型”，让两者相等，从而解出元变量。

**在哪里**：不单独存储，需要时由 Lean 现场算出。
### 三者的关系

```text
声明的类型      ∀ (A : Type@{197}) (l : list A), nat         ← 接口，调用者看得到
Body           fun (A : Type@{197}) (l : list A) => length l ← 实现，调用者看不到
子项的类型      A : Type@{197}、l : list A、length l : nat … ← 内部，检查时现场算
```

- **Step 6 的 ③** 做的事，就是把这几者对上：算出 Body 整体的类型，即 `inferType (fun A l => length l)`，要求它和声明的类型完全一样。
- **Step 6 的 ⑤** 只看**声明的类型**：Level 出现在接口里，才做成参数。
- **Step 6 的 ⑥** 中，“只在 Body 里”的 Level，指的是不出现在**声明的类型**里，只出现在 Body（以及 Body 中子项的类型）里的 Level。
### 补充：定理（Statement）
对一个定理，比如 `Lemma plus_n_O : ∀ n, n = n + 0`，Rocq 中“声明的类型”就是这个命题本身。经过 Step 2 的改写之后，命题变成了 `Rocq.plus_n_O.statement` 的 **Body**，而它的声明类型只是 `Prop`。

所以对 Statement 来说，Translator 说“出现在类型里”时，看的是**整个命题**（也就是改写后的 Body）。代码中 `if stmt then val else ty` 指的就是这个。
