### 一、PTS 是什么
#### 1. 出发点：很多类型论长着同一副骨架
1980 年代末出现了一批类型论：简单类型 λ 演算、System F、构造演算（CoC）等。Barendregt 注意到，它们的规则几乎一模一样，区别只在"有哪些层、层之间怎么搭"。于是他把它们统一成一个框架，叫**纯类型系统**（Pure Type Systems）。"纯"的意思是：只有 λ、∀、应用这些最基本的东西，没有归纳类型、没有常量定义。
#### 2. 语法：只有五种东西
项  t ::= x            变量
       |  s            一个 sort（层），比如 Prop、Type 0
       |  ∀ x : A, B   函数类型（Π 类型）
       |  λ x : A, t   函数
       |  t u          应用

类型和项用的是同一种语法，这就是"万物皆项"。
#### 3. 三张表：一个 PTS 由它们决定

|表|写法|意思|例子|
|---|---|---|---|
|**S**（sorts）|一组常量|有哪些层|{Prop, Type}|
|**A**（axioms）|一组二元组 (s₁, s₂)|s₁ 住在 s₂ 里，即 `s₁ : s₂`|(Prop, Type)，表示 `Prop : Type`|
|**R**（rules）|一组三元组 (s₁, s₂, s₃)|A 在 s₁ 层、B 在 s₂ 层时，`∀ x : A, B` 在 s₃ 层|(Type, Prop, Prop)：对一个类型量化，得到命题|

#### 4. 七条通用规则：所有 PTS 都一样
不管三张表怎么填，规则都是这七条，只是其中两条会去**查表**：

(公理)    ───────────            如果 (s₁, s₂) ∈ A        ← 查 A 表
           ⊢ s₁ : s₂

(变量)     Γ ⊢ A : s
          ─────────────────
           Γ, x : A ⊢ x : A

(弱化)     Γ ⊢ t : B    Γ ⊢ A : s
          ──────────────────────
           Γ, x : A ⊢ t : B

(∀ 形成)   Γ ⊢ A : s₁    Γ, x : A ⊢ B : s₂
          ──────────────────────────────    如果 (s₁, s₂, s₃) ∈ R   ← 查 R 表
           Γ ⊢ (∀ x : A, B) : s₃

(λ)        Γ, x : A ⊢ t : B    Γ ⊢ (∀ x : A, B) : s
          ─────────────────────────────────────
           Γ ⊢ (λ x : A, t) : ∀ x : A, B

(应用)     Γ ⊢ f : ∀ x : A, B    Γ ⊢ a : A
          ──────────────────────────────
           Γ ⊢ f a : B[x := a]

(转换)     Γ ⊢ t : A    A ≡β B    Γ ⊢ B : s
          ───────────────────────────────
           Γ ⊢ t : B

**关键点**：七条规则里，只有"公理"和"∀ 形成"这两条会去查 S、A、R。其余五条完全不关心层是什么。所以两个 PTS 的差别，**全部集中在这三张表上**。
#### 5. 例子：填不同的表，得到不同的系统

|系统|S|A|R|能表达什么|
|---|---|---|---|---|
|简单类型 λ 演算|{∗, □}|(∗, □)|(∗, ∗, ∗)|只有普通函数|
|System F|{∗, □}|(∗, □)|(∗, ∗, ∗)，(□, ∗, ∗)|还能对类型量化（多态）|
|构造演算 CoC|{∗, □}|(∗, □)|所有四种组合|依赖类型 + 多态 + 类型算子|
|λ∗|{∗}|(∗, ∗)，即 `∗ : ∗`|(∗, ∗, ∗)|什么都能写，但**不一致**（Girard 悖论）|

### 二、PTS 态射：现成的"逐格照搬"定理
#### 1. 定义
两个 PTS：P = (S, A, R) 和 P’ = (S’, A’, R’)。一个**态射**是一个只作用在层上的映射 φ : S → S'，满足：
- **保持 A**：若 (s₁, s₂) ∈ A，则 (φ(s₁), φ(s₂)) ∈ A'；
- **保持 R**：若 (s₁, s₂, s₃) ∈ R，则 (φ(s₁), φ(s₂), φ(s₃)) ∈ R'。

把 φ 推广到项上：**每个节点原样照搬，只把其中出现的层 s 换成 φ(s)**。
#### 2. 定理
> 若 φ 是从 P 到 P’ 的态射，且在 P 里 `Γ ⊢ t : A`，则在 P’ 里 `φ(Γ) ⊢ φ(t) : φ(A)`。

这就是"逐格照搬保持类型"的精确说法。
#### 3. 为什么成立：对推导树做归纳，逐条规则检查
- **公理**：P 里用了 (s₁, s₂) ∈ A。由"保持 A"，(φ(s₁), φ(s₂)) ∈ A'，所以 P' 里同一条规则也能用。
- **∀ 形成**：P 里用了 (s₁, s₂, s₃) ∈ R。由"保持 R"，P’ 里也有对应的条目。
- **变量、弱化、λ、应用**：这几条规则不查表，前提照搬过去仍然成立。由归纳假设，前提已经翻译好了，直接套用 P’ 里的同一条规则。
- **转换**：需要一个小引理：φ 和代换、β 归约都可以交换，即 φ(t[x:=u]) = φ(t)[x:=φ(u)]，且 t →β u 推出 φ(t) →β φ(u)。这是成立的，因为 φ 只换层，而 β 归约根本不碰层。

所以，**规则骨架相同时，翻译是否保持类型，只取决于三张表能不能对上**。这就是为什么它是"推得出"那部分最关键的依据：不用逐条重新论证，只需要查表。
### 三、套到 Rocq → Lean 上
#### 1. 两边的三张表（只看核心，先忽略 SProp）

| |Rocq|Lean|
|---|---|---|
|S|Prop，Type 0（= Set），Type 1，…|Sort 0（= Prop），Sort 1，Sort 2，…|
|A|`Type i : Type (i+1)`，`Prop : Type 1`|`Sort u : Sort (u+1)`|
|R|(Type i, Type j, Type (max i j))；(任意, Prop, Prop)；(Prop, Type i, Type i)|(Sort u, Sort v, Sort (imax u v))|
|额外的规则|**cumulativity**：`Type i ≤ Type j`（i ≤ j），以及 `Prop ≤ Type i`|无|

#### 2. 我们的层映射 φ，逐条检查
φ(Prop) = Sort 0，φ(Type i) = Sort (i+1)。

|Rocq 的条目|映射后|Lean 里有吗|
|---|---|---|
|A：`Type i : Type (i+1)`|`Sort (i+1) : Sort (i+2)`||
|R：(Type i, Type j, Type (max i j))|imax (i+1) (j+1) = max i j + 1||
|R：(任意 s, Prop, Prop)|imax φ(s) 0 = 0|（这正是 `imax` 的设计目的）|
|R：(Prop, Type i, Type i)|imax 0 (i+1) = i+1||
|A：`Prop : Type 1`|Lean 里是 `Sort 0 : Sort 1`，而 φ(Type 1) = Sort 2|要靠 cumulativity 才对得上|
|**cumulativity**：`Type i ≤ Type j`|Lean 没有这条规则|****|

#### 3. 结论
- **A 和 R 基本全部对得上**：所以对于不用 cumulativity 的部分，逐格照搬保持类型，这由 PTS 态射直接保证。
- **对不上的只有 cumulativity**。严格说，Rocq 的核心不是一个普通的 PTS，而是一个 **CTS**（累积类型系统），比 PTS 多一条"包容规则"：

    Γ ⊢ t : A    A ≤ B
    ──────────────────
         Γ ⊢ t : B

    Lean 没有这条规则，态射在这里找不到对应。这正是翻译器里建表、元变量、R3↓ 和 Step 7 要处理的地方。

所以，PTS 态射不仅给"推得出"的部分提供了现成的依据，还精确地告诉我们**哪里不能照搬**。
### 四、PTS 是"意思一样"的信任来源吗？
#### 不是，至少它单独不够。反例如下
**把 CoC 映射到 λ∗**：令 φ(∗) = ∗，φ(□) = ∗，也就是把所有层都映成同一个 ∗，而 λ∗ 里有 `∗ : ∗`。
- 检查：A 和 R 里的所有条目都映成 (∗, ∗) 或 (∗, ∗, ∗)，λ∗ 里都有。所以 **φ 是一个合法的态射**，CoC 的每个推导翻译过去都还合法。
- 但 λ∗ 是**不一致**的（Girard 悖论）：在 λ∗ 里，任何类型都有项，包括"假"。所以"λ∗ 里能证明 φ(A)"说明不了任何事情，翻译过去的命题已经没有意义了。

这说明：**保持类型 ≠ 保持意思。** 态射只保证结构被搬过去、推导依然成立。它不保证目标系统里的层和源系统里的层"是同一个东西"：λ∗ 把"命题层"和"类型的类型层"压成了一层，意思就全乱了。
#### 那"意思一样"还需要什么
需要再确认一件事：**φ 把每一层映到了"意思相同"的层上。** 这就要回到集合论模型：
- Rocq 的 `Type i` 在 Werner 的模型里是 V_κᵢ；
- 我们映射到 Lean 的 `Sort (i+1)`，在 Carneiro 的模型里也是 V_κᵢ；
- Rocq 的 `Prop` 和 Lean 的 `Sort 0` 都是真值 {0, 1}。

每一层都映到同一个集合上，再加上 PTS 态射保证"其余部分逐格照搬"，按组合性，整个命题就指向同一个集合。
#### 两个信任来源各管一半

|来源|保证什么|对应哪一层|
|---|---|---|
|**PTS 态射**（Barendregt）|结构被逐格搬过去，Rocq 的每个推导在 Lean 里仍成立：类型保持、可证性保持|②，规则层|
|**集合论模型**（Werner、Carneiro）|φ 把每一层映到意思相同的层上；结合组合性，整体意思相同|③，意义层|

PTS 回答的是"**能不能搬**"，模型回答的是"**搬过去还是不是同一个东西**"。两个都需要。λ∗ 那个反例里，前者成立而后者失败。
### 五、PTS 覆盖不到的地方
PTS 只是核心骨架，Rocq 和 Lean 比它多出很多东西，这些要靠别的理论补上：

|PTS 没有的|由什么补上|
|---|---|
|cumulativity（态射失败的地方）|CTS 的理论，加上我们的转接头（R3↓ 等）|
|归纳类型、构造器、`match`/`fix`/recursor|归纳定义的理论（Coquand–Paulin-Mohring、Paulin-Mohring），以及 Giménez 的 fix → recursor|
|常量和定义的展开（δ）、let（ζ）、ι 归约|对 PTS 的标准扩展，规则同样不涉及层，照搬即可|
|Level 变量（Universe 多态）|PTS 的层是常量。带变量的 Level 要看成一族 PTS，用 Level 赋值 ρ 选出具体的层（Sozeau–Tabareau；Carneiro）|
|SProp、Lean 的定义上证明无关性|单独说明：Lean 只是多出一些相等，不影响保持类型|

### 一句话
PTS 把 Rocq 和 Lean 的核心看成同一副规则骨架（七条规则），差别只在三张表（层、层的归属、∀ 落在哪层）。PTS 态射定理说：三张表对得上，逐格照搬就保持类型。我们核对过，三张表除了 cumulativity 全部对得上。

但 PTS 只保证"能搬过去、推导依然成立"，不保证"意思一样"。λ∗ 的例子说明，一个合法的态射也可能把意思全搞乱。"意思一样"还需要集合论模型来确认：每一层都映到了同一个集合上。

所以信任来源是两样合起来：**PTS 态射（结构）+ 集合论模型（意思）**。
