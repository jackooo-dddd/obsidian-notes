
Rocq Kernel 的项（`constr`）和 Lean Kernel 的项（`Expr`）对照：

| Rocq                                          | Lean `Expr`         | 能不能直接对应                                |
| --------------------------------------------- | ------------------- | -------------------------------------- |
| `Rel n`（de Bruijn 变量）                         | `bvar n`            | 能：编号方式相同，0 都是最内层的 binder               |
| `Sort`                                        | `sort`              | 基本能：两边都有分层，但规则不同（Lean 没有 Cumulativity） |
| `Prod`（∀）                                     | `forallE`           | 能                                      |
| `Lambda`                                      | `lam`               | 能                                      |
| `LetIn`                                       | `letE`              | 能                                      |
| `App f [a₁ … aₙ]`                             | `app`（一次一个参数）       | 能：多个参数就是连续地 `app`（`mkAppN`）            |
| `Const / Ind / Construct` + Universe Instance | `const 名字 [levels]` | 能：Lean 把类型和构造器也当作常量                    |
| `Case`（match）                                 | **没有**              | 不能：改写成 recursor `I.rec`                |
| `Fix`（递归）                                     | **没有**              | 不能：降级成 recursor                        |
| `Cast`                                        | **没有**              | 不能：检查可转换后擦除                            |


Rocq 和 Lean 虽然是两个不同的系统，但它们的核心其实是“同一个家族”出来的：都建立在一种叫依赖类型论的理论上，更具体地说，都属于 CIC（Calculus of Constructions 加上归纳类型）这一派。打个比方，就像两种从同一个祖先语言发展出来的方言，最基本的那些词，意思和用法都是一样的。
那怎么判断一个“词”，也就是 AST 里的一种节点，在两边是不是同一个意思呢？就看两件事：第一，怎么判断它合不合法、它是什么类型（类型规则）；第二，它怎么计算出结果（计算规则）。
我们以 `app` 为例。`app` 是 application 的缩写，意思就是**函数调用**：把一个函数用到某个参数上，比如 `length l`、`f a`，或者 `add 2 3`，在 AST 里都是一个 `app` 节点，里面记着“调用的是哪个函数”和“传进去了哪些参数”。对于函数调用，我们关心两件事：一是这个调用合不合法、结果是什么类型；二是这个调用怎么算出结果。这两件事分别由下面两条规则决定，而 Rocq 和 Lean 在这两条规则上是完全一样的。
- **类型规则**（Π-消去）：这条规则说的是：一个函数调用之后，结果是什么类型。如果有一个函数 `f`，它要求输入的东西属于类型 `A`，那么只要我们真的给它一个属于 `A` 的 `a`，调用 `f a` 就是合法的。Rocq 和 Lean 判断函数调用是否合法，用的都是这一条
- **计算规则**（β 规约）：这条规则说的是：一个函数调用怎么算出结果。如果函数是直接写出来的，比如 `fun x => x + 1`，我们把 `3` 传进去，计算的方法就是把函数体里所有的 `x` 都换成 `3`，得到 `3 + 1`。这一步叫 β 规约，就是我们平常理解的“代入”。Rocq 和 Lean 算函数调用，都是这样代入的。所以只要翻译前后函数体是一样的，在两边算出来的结果也就是一样的。

| 节点                     | 类型规则（怎么判断合法、是什么类型）                                           | 计算规则（怎么算）                              | 两边一样吗                                                                            |
| ---------------------- | ------------------------------------------------------------ | -------------------------------------- | -------------------------------------------------------------------------------- |
| `Rel n` / `bvar n`（变量） | 上下文里有 `x : A`，那么 `x` 的类型就是 `A`                               | 没有自己的计算规则；只在“代入”时被替换                   | 一样，编号方式也相同                                                                       |
| `Prod` / `forallE`（∀）  | `A` 是类型、`B` 是类型，那么 `∀ (x : A), B` 也是类型，它所在的层由 `A` 和 `B` 的层决定 | 没有，类型本身不计算                             | 基本一样：都用 `max` 决定层，都让 `Prop` 是非直谓的（`∀ … , 命题` 仍然是命题）；Lean 用 `imax` 写这一点，翻译时要对上    |
| `Lambda` / `lam`（fun）  | 在 `x : A` 的前提下 `t : B`，那么 `fun x => t : ∀ (x : A), B`        | 和 `app` 一起构成 β 规约                      | 一样                                                                               |
| `LetIn` / `letE`（let）  | `v : A`，在 `x := v` 下 `t : B`，那么整体的类型是 `B` 中 `x` 换成 `v`       | ζ 规约：`let x := v in t` 计算成 `t[x := v]` | 一样                                                                               |
| `Sort` / `sort`        | `Type u` 自己住在 `Type (u+1)`                                   | 没有                                     | **不完全一样**：Rocq 多了一条 Cumulativity（`Type@{i}` 可以当 `Type@{j}` 用，只要 `i ≤ j`），Lean 没有 |
