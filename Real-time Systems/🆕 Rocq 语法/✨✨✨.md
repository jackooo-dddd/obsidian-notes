# 万物皆项

在 Rocq 的内核里，所有东西都是项。

| 平时叫它 | 例子                        | 内核里 |
| ---- | ------------------------- | --- |
| 数据   | `3`、`true`                | 项   |
| 函数   | `double`、`fun n => n + 1` | 项   |
| 类型   | `nat`、`nat -> nat`        | 项   |
| 命题   | `n + 0 = n`               | 项   |

- 每个良类型（合法）的项都有一个类型。比如 `3` 的类型是 `nat`，`nat` 的类型是 `Set`。
- 有些项本身也是类型，比如 `nat` 和函数类型 `nat -> nat`。判断一个项是不是类型，就看它的类型：如果类型是一个 **sort**（`Prop`、`Set` 或 `Type@{i}`），它就是类型。

内核里的项只能由十几种节点组合而成，内核对于所有的项会：

- 用**同一套类型规则**做类型推导（每种节点一条规则）；
- 用**同一套归约规则**计算（β、δ、ι、ζ）；
- 用**同一个可转换检查**判断是否相等。

内核不需要分别处理"数"、"类型"、"证明"，它只处理项。

# 函数项

绝大部分的声明都是函数。

`Definition P (n : nat) : Prop := n + 0 = n.` 交给内核之前，Rocq 会对声明进行语法上的展开，内核是不知道源码里面的任何简写的。

声明里写在名字后面的参数 `(n : nat)`，会同时放到两个地方：

```text
Definition P (n : nat) : Prop := n + 0 = n.
             └───┬───┘   └┬─┘    └───┬───┘
               参数     返回类型    定义体

函数类型：forall (n : nat), Prop              ← 参数变成 Prod，body 是返回类型 Prop
函数项：  fun (n : nat) => n + 0 = n              ← 参数变成 Lambda，body 是定义体
          = fun (n : nat) => @eq nat (Nat.add n 0) n   ← 同一个项，展开记号：+ 是 Nat.add，= 是 eq
```

- 函数项 `fun (n : nat) => n + 0 = n` 有三部分：参数名 `n`、参数类型 `nat`、定义体 `n + 0 = n`。定义体可以是任何合法类型的项。
- 函数类型 `forall (n : nat), Prop` 也有三部分：参数名 `n`、参数类型 `nat`、返回类型 `Prop`。返回类型必须是一个**类型**（它的类型是 sort）。
- 函数项的类型，就是"同样的参数 + 定义体的类型"组成的函数类型：定义体 `n + 0 = n` 的类型是 `Prop`，所以函数项的类型是 `forall (n : nat), Prop`。
- `eq` 的类型是 `eq : forall (A : Type), A -> A -> Prop`，它接收三个参数：
  - **A**：两边的类型，这里是 `nat`；
  - **左边**：`Nat.add n 0`；
  - **右边**：`n`。
- 平时写 `n + 0 = n` 时不用写 `nat`，因为 Rocq 会根据两边自动推断出 A。这种参数叫**隐式参数**。前面加 `@`，就是把隐式参数也显式写出来。在内核里，隐式参数和普通参数一样，都要写在项里。

## 进入内核

`fun (n : nat) => n + 0 = n` 是一个函数项，在内核里用 `Lambda` 节点表示，源码里的 `fun` 就对应 `Lambda`。函数项的三部分正好是 `Lambda` 的三个输入：参数名、参数类型、定义体。参数类型和定义体本身也都是项。参数名只用于显示，定义体里通过编号 `Rel 0` 引用参数。

`@eq nat (Nat.add n 0) n` 是一个函数调用，在内核里用 `App` 节点表示。`App` 的输入是**被调用的项**和**参数列表**。被调用的项可以是任何类型为函数类型的项，这里是归纳类型 `eq`，它的类型是 `forall (A : Type), A -> A -> Prop`。这里给了三个参数：

- `A`：两边的类型 `nat`；
- 左边：`Nat.add n 0`，它本身也是一个 `App`；
- 右边：`n`，即 `Rel 0`。

```text
树形结构
fun (n : nat) =>                      Lambda
  @eq                                 App 的函数：eq
    nat                               参数 1：Ind nat
    (Nat.add n 0)                     参数 2：App(Nat.add, [n, O])
    n                                 参数 3：n
```

`Definition P (n : nat) : Prop := n + 0 = n.` 在内核里完整的样子是：

```text
类型：  Prod(n, Ind nat, Sort Prop)

函数项：Lambda( n, Ind nat,
          App( Ind eq,                                        ← 被调用的项：归纳类型 eq
               [ Ind nat,                                     ← 参数 A
                 App(Const Nat.add, [Rel 0, Construct O]),    ← 左边：n + 0
                 Rel 0 ] ))                                   ← 右边：n
```

## 内核会怎么处理函数项

对于一个项，内核要做的事情就是确认这个项是合法的，比如说引用的变量，其它函数都存在、参数类型可以对上。

内核还需要给每一个项，算出这个项的类型。

```text
fun (n : nat) => n + 0 = n
Lambda(n, Ind nat,
  App( Ind eq,                                        ← 被调用的项：归纳类型 eq
       [ Ind nat,                                     ← 参数 A
         App(Const Nat.add, [Rel 0, Construct O]),    ← 左边：n + 0
         Rel 0 ] ))                                   ← 右边：n
```

```text
内核看到 Lambda(n, Ind nat, body)：
├─ ① 检查参数类型 Ind nat 是不是类型
│    ├─ 在环境里查 nat：已声明的归纳类型，类型是 Set
│    └─ Set 是 sort，所以 nat 是类型 ✓
├─ ② 把 n : nat 加入上下文（之后 Rel 0 就指 n）
├─ ③ 在这个上下文下，推定义体 @eq nat (Nat.add n 0) n 的类型
│    内核里函数调用的节点是 App：被调用的函数是 eq，后面跟三个参数
│    ├─ 查被调用的项 Ind eq 的类型：∀ (A : Type), A → A → Prop
│    ├─ 参数 1：Ind nat
│    │    ├─ 要求类型 Type；nat 的类型是 Set，Set 可以当 Type 用 ✓
│    │    └─ 代入 A := nat，剩下  nat → nat → Prop
│    ├─ 参数 2：App(Const Nat.add, [Rel 0, Construct O])
│    │    ├─ 这也是一个 App，用同样的方法推它的类型：
│    │    │    ├─ Const Nat.add 的类型：nat → nat → nat（在环境里查）
│    │    │    ├─ Rel 0 即 n，类型 nat ✓（在上下文里查）
│    │    │    ├─ Construct O 的类型 nat ✓（在环境里查）
│    │    │    └─ 结果：nat
│    │    ├─ 与要求的 nat 比较 ✓
│    │    └─ 剩下  nat → Prop
│    ├─ 参数 3：Rel 0
│    │    ├─ 指上下文里最近的变量 n，它的类型是 nat
│    │    ├─ 与要求的 nat 比较 ✓
│    │    └─ 剩下  Prop
│    └─ 定义体的类型是 Prop
│       （eq 本身不再检查：它在声明时已经检查过）
└─ ④ Lambda 合法，类型是  ∀ (n : nat), Prop
```

## 函数的名字

在内核看来，函数本身是匿名的，名字由声明（`Definition`、`Lemma`、`Theorem` 等）给出。函数就是一个项（`Lambda`），它有一个类型（函数类型）。

以 `Definition P (n : nat) : Prop := n + 0 = n.` 为例，内核检查这条声明时：

1. 确认声明的类型 `∀ (n : nat), Prop` 是一个类型；
2. 确认定义体 `fun (n : nat) => n + 0 = n` 合法，并推出它的类型 `∀ (n : nat), Prop`；
3. 比较两者，相同，于是接受这条声明；
4. 把它加入全局环境，记录**名字 `P`、类型、定义体**，以及它是否可以展开（透明还是不透明）。

之后在任何项里引用 `P` 时，内核看到的是 `Const P`，意思是"环境里叫 P 的那个东西"：

- **推类型**时，直接查到它的类型 `∀ (n : nat), Prop`，不再重新检查 P 的定义体；
- **需要计算**时（例如判断 `P 5` 和 `5 + 0 = 5` 是否相等），需要两条归约规则：
  1. **δ**：把 `Const P` 换成 P 在环境里存的定义体，一个 `Lambda`；
  2. **β**：把 `Lambda` 的 body 里的参数（`Rel 0`）换成实际参数 5。
- 归约（δ、β 等）只在**判相等需要时**才发生。而单纯推 `Nat.add n 0` 的类型，只需要知道 `Nat.add` 的**类型**，`Nat.add` 的函数定义体不会被展开。[[引用函数时的规约]]

# Rocq VS Lean

```coq
Definition P : nat -> Prop :=  fun (n : nat) => @eq nat (Nat.add n 0) n.
```

```lean
def P : nat → Prop := fun (n : nat) => eq.{1} nat (Nat.add n nat.O) n
```

| 语言         | 函数项                                               |
| ---------- | ------------------------------------------------- |
| Rocq       | `fun (n : nat) => @eq nat (Nat.add n 0) n`        |
| Lean（翻译结果） | `fun (n : nat) => eq.{1} nat (Nat.add n nat.O) n` |

```text
Rocq 内核                          Lean 内核（摊平 app）                 含义
─────────────────────────────────  ──────────────────────────────────  ──────────────────
Lambda n                           lam n                                函数
├─ Ind nat                         ├─ const nat                         参数类型
└─ App                             └─ app*                              调用 eq，给 3 个参数
   ├─ Ind eq                          ├─ const eq.{1}                   被调用的项
   ├─ Ind nat                         ├─ const nat                      参数 A
   ├─ App                             ├─ app*                           左边：n + 0
   │  ├─ Const Nat.add                │  ├─ const Nat.add               被调用的项
   │  ├─ Rel 0                        │  ├─ bvar 0                      n
   │  └─ Construct O                  │  └─ const nat.O                 0
   └─ Rel 0                           └─ bvar 0                         右边：n
```

比如说，我们现在要说明，Rocq 里面的函数项，要和翻译到 Lean 里面的函数项是一样的，我们就去说明源内核的每一步推理，在目标内核里我们都可以找到，对这一步推理的对应。

## 总体思路

### 0. 定义翻译

翻译是一个按节点定义的函数：每个 Rocq 节点按对照表换成对应的 Lean 节点，子项分别翻译，叶子换成对照表规定的对应物。由这个定义，每个 Rocq 子项都有唯一一个对应的 Lean 子项，两棵树形状相同，不会多出或少掉子项。这一点不需要另外论证。

例外是规则中明确写出的几处：多元调用拆成嵌套调用、插入 `PULift`、删除 `Cast`、`Case`/`Fix` 改写为 `rec`、原生值换成模型。这几处单独论证。

### 1. 要论证的事

对树里的每一部分，在两边上下文对应的前提下，Lean 内核给出的类型，正是 Rocq 内核给出的类型的翻译。这一点对每种节点逐个说明。

说明过程中要用到两条关于整个翻译的一般性质，它们各自单独证明一次：

- **替换对应引理**：在任何项里把一个变量换成另一个项，先换再翻译，等于先翻译再换。例如调用时，把函数类型里的参数换成实际参数，两边得到的剩下的类型仍然对应。
- **相等判断对应引理**：Rocq 认为两个项相同（计算后相同），Lean 也认为它们的翻译相同。例如调用时比较参数类型和要求的类型，两边给出相同的判断。

[[引理说明]]

这两条性质主要用在"调用"这种节点，以及检查整个声明的最后一步；其余节点只需要子项的类型对应、上下文对应和环境对应。

### 2. 每种节点都能保持这件事

只要一个节点里面的各部分已经对应，这个节点本身也对应。原因有三点：

- **规则一样**：两边内核检查这种节点，用的是同一条规则。比如检查一个函数，都是先看参数类型是不是一个类型，再算函数体的类型，最后把两者组成函数类型。
- **用到的东西对应**：检查时用到三样东西，两边都是对应的：
    - **子项**：由翻译的定义，每个子项都有唯一对应的翻译；
    - **已经引入的变量**：每进入一层函数，两边都加入对应的变量，编号相同；
    - **引用的全局声明**：它们已经先翻译好了。
- **中间的判断一样**：检查时要回答几种问题，两边给出相同的答案：
    - 内核看的是这个项的类型。如果类型不是直接写成层或函数类型（比如是一个名字 `F`），两边都会先把它算到最外层露出来（例如把 `F` 展开成 `nat -> nat`），再判断。因为两边的计算规则相同，算出来的最外层也是对应的节点，所以判断结果相同。
    - **"这两个类型是不是相同"**：由**相等判断对应**引理保证。例如调用时，Rocq 判断"参数实际的类型"和"函数要求的参数类型"相同（比如 `Nat.add n 0` 的类型 `nat` 和 `eq` 要求的 `nat`），那么翻译后 Lean 也判断这两个类型的翻译相同。
    - **"代入参数之后，剩下的类型是什么"**：由**替换对应**引理保证。例如调用 `eq` 时，给出第一个参数 `nat`，Rocq 把 `eq` 类型里的 A 换成 nat，剩下 `nat → nat → Prop`；Lean 在翻译后的类型里，把 A 换成 nat 的翻译，得到的正好是 `nat → nat → Prop` 的翻译。

每种节点具体用到的东西：

| 节点                                        | 检查时用到                           |
| ----------------------------------------- | ------------------------------- |
| 变量（`Rel` / `bvar`）                        | 已经引入的变量                         |
| 全局引用（`Ind`、`Const`、`Construct` / `const`） | 引用的全局声明                         |
| 函数（`Lambda` / `lam`）                      | 子项；新加入的变量                       |
| 函数类型（`Prod` / `forallE`）                  | 子项；新加入的变量；层级对照表                 |
| 调用（`App` / `app`）                         | 子项；相等判断对应（比较参数类型）；替换对应（算出剩下的类型） |

### 3. 所以整个函数也对应

从最里面的叶子开始，一层一层往外推，每一层都对应，一直推到最外层的函数。结果是：Rocq 内核接受这个函数，翻译后 Lean 内核也接受；Rocq 算出的函数类型，翻译过去正好就是 Lean 算出的函数类型。

## 例子

```coq
Definition P : nat -> Prop := fun (n : nat) => @eq nat (Nat.add n 0) n.
```

**读法**：每一行里，两边内核**用同一条规则**处理**对应的子项**，**查到对应的东西**，**得出对应的类型**。

| 步骤 | 子项（Rocq 节点 / Lean 节点） | Rocq 内核 | Lean 内核 | 为什么对应 |
| --- | --- | --- | --- | --- |
| **① 检查参数类型** | `Ind nat` / `const nat` | 查环境：`nat` 的类型是 `Set`，是层 | 查环境：`nat` 的类型是 `Sort 1`，是层 | 查到的是同一个声明的两个版本（环境对应）；`Set ↦ Sort 1` |
| **② 进入函数体** | — | 上下文加入 `n : nat` | 上下文加入 `n : nat` | 上下文对应，编号相同 |
| **③ 检查定义体**（调用规则） | `App(Ind eq, […])` / `app*(const eq.{1}, …)` | | | |
| 被调用的项 | `Ind eq` / `const eq.{1}` | 查环境：`∀ (A : Type@{u}), A → A → Prop` | 查环境：`∀ (A : Sort 1), A → A → Prop` | 环境对应；层级换算 |
| 参数 1 | `Ind nat` / `const nat` | 实际类型 `Set`，要求 `Type@{u}`：`Set ≤ Type@{u}` | 实际类型 `Sort 1`，要求 `Sort 1`：相同 | **唯一用到"小一层当大一层用"的地方**；翻译时把 `eq` 的层级选成 `1`，Lean 一侧正好相同 |
| 代入 A := nat | — | 剩下 `nat → nat → Prop` | 剩下 `nat → nat → Prop` | **替换对应**（引理 1） |
| 参数 2（调用规则，递归） | `App(Const Nat.add, [Rel 0, Construct O])` / `app*(const Nat.add, bvar 0, const nat.O)` | | | |
| 被调用的项 | `Const Nat.add` / `const Nat.add` | 查环境：`nat → nat → nat` | 查环境：`nat → nat → nat` | 环境对应 |
| 参数 n | `Rel 0` / `bvar 0` | 查上下文：`nat`；要求 `nat` | 查上下文：`nat`；要求 `nat` | 上下文对应；**相等判断对应**（引理 2） |
| 参数 0 | `Construct O` / `const nat.O` | 查环境：`nat`；要求 `nat` | 查环境：`nat`；要求 `nat` | 环境对应；引理 2 |
| 结果 | — | `nat` | `nat` | 引理 1（箭头不依赖参数，代入后不变） |
| 与要求的类型比较 | — | 要求 `nat`，实际 `nat` | 要求 `nat`，实际 `nat` | 引理 2 |
| 代入之后 | — | 剩下 `nat → Prop` | 剩下 `nat → Prop` | 引理 1 |
| 参数 3 | `Rel 0` / `bvar 0` | 查上下文：`nat`；要求 `nat` | 查上下文：`nat`；要求 `nat` | 上下文对应；引理 2 |
| 代入之后 | — | 剩下 `Prop`，即**定义体的类型** | 剩下 `Sort 0`（即 `Prop`） | 引理 1；`Prop ↦ Sort 0` |
| **④ 得出函数的类型**（函数规则） | `Lambda` / `lam` | `∀ (n : nat), Prop` | `∀ (n : nat), Prop` | 两边都用"参数类型 + 定义体的类型"组成函数类型 |
| **⑤ 检查整个声明** | `P` | 算出的类型与声明的 `nat -> Prop` 相同 | 算出的类型与声明的 `nat → Prop` 相同 | 引理 2 |
