# 归约与定义等价
## 1. 基本概念

|概念|意思|
|---|---|
|**归约**（reduction，也写作"规约"）|按计算规则把项化简一步|
|**规范化**（normalization）|一直归约，直到不能再化简为止|
|**范式**（normal form）|规范化得到的结果|
|**弱头范式**（weak head normal form，whnf）|只把**最外层**算到不能再算，里面的部分保持原样|

## 2. 归约规则
下面的例子都基于这两条定义：

```coq
Definition P (n : nat) := n + 0 = n.
(* Rocq 中 add 对第一个参数做 match：
   0 + m     ↦ m
   S p + m   ↦ S (p + m)                *)
```

|规则|做什么|例子|
|---|---|---|
|**δ**（delta）|把常量展开成它的定义|`P 5` → `(fun n => n + 0 = n) 5`|
|**β**（beta）|函数应用：把参数代入函数体|`(fun n => n + 0 = n) 5` → `5 + 0 = 5`|
|**ι**（iota）|`match` 或 `fix` 遇到构造子时，选出对应分支|`match O with O => true \| S _ => false end` → `true`|
|**ζ**（zeta）|展开 `let`|`let x := 3 in x + 1` → `3 + 1`|
|**η**（eta）|`fun x => f x` 和 `f` 相等|`fun n => S n` ≡ `S`|

一个完整的计算通常要组合多条规则。例如 `0 + 0` 化简为 `0`：
1. **δ**：展开 `add`，得到一个 `fix`；
2. **ι**：`fix` 的递减参数是构造子 `O`，展开一层，进入 `match`；
3. **ι**：`match O` 选中第一个分支；
4. **β**：把参数代入，得到 `0`。

η 和其他四条不太一样：它通常不作为"往前化简"的一步，而是在**判断两个项是否相等**时使用（见第 4 节）。
## 3. 内核并不总是完全展开

内核通常只归约到**弱头范式**：把最外层算出来，看清它是什么（Π、λ、构造子、层……）就停下，里面的部分不动。

### 例 1：判断 `F` 是不是函数类型

```coq
Definition F : Type := nat -> nat.
```

内核对 `F` 做 δ 归约，得到 `nat -> nat`，即 `Prod(_, nat, nat)`。最外层已经是 `Prod`，就停下来，不再计算内部。**`nat -> nat` 和 `forall n : nat, nat`** 在内核里都直接存成 `Prod`。唯一的区别是**变量名**。变量名对内核没有意义。
- `forall` 表达式变成内核里的 `Prod` 项，靠的是翻译（解析 + 精化），和 δ 等归约规则都没有关系。Rocq 处理源码时，会把 `A -> B` 和 `forall x : A, B` 都翻译成 product：先解析成语法树，再经过名字解析和精化（elaboration），最后得到 `Prod(_, A, B)`。所以项送进内核时已经是 `Prod`，这一步不需要任何归约。
**δ 归约**是把一个**常量**展开成它的定义。之所以用到 δ，是因为 `F` 是一个定义：

| 项 | 内核里是什么 | 要不要 δ |
| --- | --- | --- |
| `nat -> nat` | 直接就是 `Prod(_, nat, nat)` | 不要 |
| `F` | 一个 `Const` 节点，指向 `F` | 要：δ 展开后才得到 `Prod(_, nat, nat)` |

- `F` 和 `nat -> nat`：**不是**同一个项，一个是 `Const`，一个是 `Prod`。但 `F` 经 δ 展开后等于 `nat -> nat`，所以两者**定义等价**。

### 例 2：`forall n, P n`

最外层本来就是 `Prod(n, nat, P n)`，已经是弱头范式。只有在需要比较 body 时，内核才会继续把 `P n` 归约成 `n + 0 = n`。

这样做是为了效率：完全展开可能非常慢，而大多数检查只需要知道最外层是什么。前面看过的内核代码正是这样做的，例如检查函数调用时，先把函数的类型化简到弱头范式，再看它是不是 `Prod`（Rocq 的 `whd_stack`，Lean 的 `whnf`）。

## 4. 可转换性
内核判断两个类型是否相同时，不要求字面一致，只要求它们**能通过归约（以及 η）变成同一个东西**。这叫**可转换**（convertible）。

```coq
Lemma add_0_r : forall n : nat, n + 0 = n.   (* 假设已证明 *)
Check add_0_r : forall n : nat, P n.         (* 通过 *)
```

`P n` 经过 δ、β 归约就是 `n + 0 = n`，两边可转换，内核认为它们是同一个类型。

内核判断可转换时，并不是把两边都完全规范化再比，而是**按需归约**：先比较最外层；不一样就把某一边再算一步；最外层一样了，再逐个比较子项。
## 5. 定义等价与命题等价
所有归约规则合在一起，决定了**定义等价**（definitional equality，也叫判断等价）：内核认为哪些项**本来就是同一个**，不需要证明。

它和**命题等价**（propositional equality，即 `a = b`）是两个不同层次的概念：

| |定义等价|命题等价|
|---|---|---|
|写法|没有写法，是内核的判断|`a = b`，是一个命题|
|怎么成立|内核自动算出来|需要提供证明|
|例子|`0 + n` 和 `n`|`n + 0` 和 `n`|

最后一行是一个很好的对比：
- `0 + n = n`：`add` 对第一个参数做 `match`，第一个参数是 `0`，ι 直接算出 `n`。两边**定义等价**，证明只需 `eq_refl`；
- `n + 0 = n`：第一个参数是变量 `n`，`match` 卡住算不下去。两边**不定义等价**，必须对 n 做归纳才能证明。

两者都成立，但成立的层次不同。
## 6. 这些规则从哪里来
这些规则来自 λ 演算和类型论，不是 Rocq 发明的：

|规则|来源|
|---|---|
|β|λ 演算（Church），只要语言里有函数和函数应用就有它|
|δ|展开定义，任何允许给项起名字的系统都有|
|ι|归纳类型的计算规则。Martin-Löf 类型论里，消去子遇到构造子时的计算规则就是这一类；"ι"这个名字是 Rocq/CIC 传统的叫法|
|ζ|展开 `let`。"ζ"同样是 Rocq 的叫法|
|η|函数外延性的一种弱形式：对函数 f，`fun x => f x` 和 `f` 相同|

## 7. 和 Lean 的对比（与翻译相关）

|            | Rocq                         | Lean                                       |
| ---------- | ---------------------------- | ------------------------------------------ |
| β、δ、ζ、η    | 有                            | 有，规则相同                                     |
| ι          | 作用于 `match` 和 `fix`          | 作用于递归子 `rec`（Lean 内核没有 `match` 和 `fix` 节点） |
| 判断两个类型可转换时 | 允许"小一层当大一层用"（累积性，`conv_leq`） | 要求严格相等（`is_def_eq`）                        |
| 额外的定义等价    | —                            | 同一命题的任意两个证明定义等价（证明无关性）；结构体的 η              |

对翻译的意义：
- β、δ、ζ、η 两边相同，所以节点逐个对应时，计算也对应；
- ι 不同，所以 `match`/`fix` 要改写成 `rec`，并单独说明计算结果相同；
- 累积性只有 Rocq 有，所以翻译时插入 `PULift`。
