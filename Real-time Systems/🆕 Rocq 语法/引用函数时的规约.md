# 函数应用的计算：δ 与 β
## 1. 要点
- 计算一个**有名字的**函数的应用，例如 `P 5`，需要两条归约规则：
    1. **δ**：把 `Const P` 换成 P 在环境里存的定义体，一个 `Lambda`；
    2. **β**：把这个 `Lambda` 的 body 里的参数（`Rel 0`）换成实际参数 5。
- 匿名的函数应用只需要 β；不透明的常量（以 `Qed` 结束）不能 δ；归纳类型和构造子没有定义体，不会被展开。
- 这些归约只在**需要判断两个项是否相等**时才发生。推 `P 5` 的类型时，只查 P 的类型，不展开 P。
- 内核**按需归约**：一旦两边已经相同就停下，不会把项完全展开。
## 2. 推类型时不归约，判断相等时才归约
内核对 `P 5` 可能做两件不同的事：

|要做的事|需要归约吗|怎么做|
|---|---|---|
|**推 `P 5` 的类型**|不需要|查 `Const P` 的类型 `∀ (n : nat), Prop`；检查 5 的类型是 nat；代入后得到 `Prop`。P 不会被展开|
|**判断 `P 5` 和 `5 + 0 = 5` 是否相等**|需要|先 δ 再 β，见第 3 节|

δ 和 β 只在需要比较的时候才发生，比如检查 `add_0_r 5 : P 5` 能不能当作 `5 + 0 = 5` 的证明来用。
### 例：推 `Nat.add n 0` 的类型时发生了什么
推类型时，内核不会对 `Nat.add n 0` 做任何归约，`Nat.add` 也不会被展开。发生的只有三种操作：

|操作|内容|是不是归约|
|---|---|---|
|**查类型**|在环境里查到 `Nat.add : nat → nat → nat`；在上下文里查到 `n : nat`；在环境里查到 `O : nat`|不是，只是查找|
|**代入**|每处理一个参数，把类型最外层 Π 的变量换成这个参数，得到剩下的类型：`nat → nat → nat` → `nat → nat` → `nat`|不是对项的归约，是对**类型**做替换|
|**比较**|参数的类型 nat 和要求的 nat 是否相等|两边字面上就相同，不需要化简|

关于"代入"：`Nat.add` 的类型是不依赖参数的箭头，所以替换后形状不变。如果是依赖类型，替换就会改变剩下的类型。例如 `eq : ∀ (A : Type), A → A → Prop`，给出第一个参数 nat 后，剩下的类型变成 `nat → nat → Prop`，后面两个参数要求的类型 nat 就是这样来的。
## 3. 计算 `P 5` 的完整过程

```text
P 5
= App(Const P, [5])

  ── δ：把 Const P 换成定义体 ──►

App( Lambda(n, Ind nat,
       App(Ind eq, [ Ind nat,
                     App(Const Nat.add, [Rel 0, Construct O]),
                     Rel 0 ])),
     [5] )

  ── β：把 body 里的 Rel 0（即 n）都换成 5 ──►

App(Ind eq, [ Ind nat,
              App(Const Nat.add, [5, Construct O]),
              5 ])
= @eq nat (Nat.add 5 0) 5
= 5 + 0 = 5
```

到这里，结果和 `5 + 0 = 5` 字面上完全相同，内核判定两者相等，停下。
## 4. 不是每个应用都会归约

|应用|会发生什么|
|---|---|
|`P 5`，P 是透明定义|δ + β|
|`(fun n => n + 0 = n) 5`，没有名字|只需要 β|
|`P 5`，P 以 `Qed` 结束（不透明）|不能 δ，停在 `P 5`|
|`@eq nat …`，eq 是归纳类型|没有定义体可以展开，它本身就是结果|
|`S 5`，S 是构造子|同上，不再化简|

准确的说法是：**有名字的透明函数，计算其应用时要先 δ 展开名字，再 β 代入参数。**
## 5. 还可以继续算，但内核按需停下
第 3 节的结果 `@eq nat (Nat.add 5 0) 5` 里，`Nat.add 5 0` 还能继续算：

```text
Nat.add 5 0
  ── δ：展开 Nat.add，得到一个 fix
  ── fix 展开 + ι：对第一个参数 5（即 S 4）做 match，选 S 分支
  ── β：代入参数
  ── …… 重复，直到第一个参数变成 O
  ⟶ 5
```

最后得到 `5 = 5`。内核会不会继续算，取决于在和什么比较：
- 和 `5 + 0 = 5` 比较：β 之后两边字面上已经相同，**停下**；
- 和 `5 = 5` 比较：两边还不同，内核**继续**算 `Nat.add 5 0`，直到得到 `5`，再比较。

这就是**按需归约**：内核只算到能做出判断为止，不会每次都完全展开。
