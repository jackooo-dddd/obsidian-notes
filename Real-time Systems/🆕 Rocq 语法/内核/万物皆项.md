## 1. 只有一种语法类别
Rocq 内核里只有一种语法类别：**项**（`constr`）。我们平时以为是不同种类的东西，在内核里都是项：

|平时叫它|例子|内核里|
|---|---|---|
|数据|`3`、`true`|项|
|函数|`double`、`fun n => n + 1`|项|
|类型|`nat`、`nat -> nat`|项|
|命题|`n + 0 = n`|项|
|证明|`add_0_r`、`eq_refl`|项|
|sort|`Prop`、`Set`、`Type`|项|

所以"是不是类型"不是项的**种类**，而是一种**关系**：

> 一个项的类型是 sort，它就是一个类型。

比如 `nat : Set`，所以 `nat` 是类型；`3 : nat`，而 `nat` 不是 sort，所以 `3` 不是类型。"是不是命题"也一样：类型是 `Prop` 的项就是命题。
## 2. 项由固定的几种节点构成
任何项都只能由下面这些节点组合而成（定义在 `kernel/constr.mli`）：

| 节点                             | 表示                 | 例子                           |
| ------------------------------ | ------------------ | ---------------------------- |
| `Rel`                          | 绑定变量（de Bruijn 编号） | `fun n => …` 里的 `n`          |
| `Var`                          | section 里声明的具名变量   | `Variable A : Type.` 之后的 `A` |
| `Sort`                         | sort               | `Prop`、`Set`、`Type@{i}`      |
| `Prod`                         | 函数类型               | `forall n : nat, n + 0 = n`  |
| `Lambda`                       | 函数                 | `fun n : nat => n + n`       |
| `App`                          | 函数应用               | `Nat.add n n`                |
| `LetIn`                        | 局部定义               | `let x := 3 in x + 1`        |
| `Cast`                         | 类型标注               | `(t : T)`                    |
| `Const`                        | 全局常量               | `double`、`add_0_r`           |
| `Ind`                          | 归纳类型               | `nat`、`eq`                   |
| `Construct`                    | 构造子                | `O`、`S`、`eq_refl`            |
| `Case`                         | 模式匹配               | `match n with …`             |
| `Fix` / `CoFix`                | （余）递归函数            | `Nat.add` 的定义体               |
| `Proj`                         | 原生记录的投影            | 记录 `r` 的某个字段                 |
| `Int`、`Float`、`String`、`Array` | 原生字面量              | 63 位整数 `42`、浮点数              |

另外还有 `Meta`、`Evar`（元变量和存在变量）。它们只在交互构造证明的过程中出现，内核接受的最终项里不能含有它们。

需要区分一点：`Const`、`Ind`、`Construct` 是**对全局声明的引用**，不是声明本身。归纳类型 `nat` 的声明（有哪些构造子、各自是什么类型）存放在全局环境里；项里的 `Ind nat` 只是指向它。
## 3. 项可以出现在任何需要项的位置
因为只有一种类别，任何项都可以：

|用法|例子|
|---|---|
|**当参数**|类型也能传给函数：`fun (A : Type) (x : A) => x`（多态恒等函数）；`nat_ind` 接收 `P : nat -> Prop`|
|**当返回值**|函数可以返回类型，这就是**类型族**：`fun n : nat => vec nat n`|
|**出现在类型里**|数据可以写进类型：`vec A 3` 里的 `3`，`5 + 0 = 5` 里的 `5`。这就是**依赖类型**|

在很多编程语言里，"值"和"类型"是两套分开的语法，不能这样混用。Rocq 能做依赖类型，正是因为它们都是项。
## 4. 用同一套规则处理
所有的项都：
- 用**同一套类型规则**推导类型，每种节点一条规则；
- 用**同一套归约规则**计算（β、δ、ι、ζ）；
- 用**同一个可转换检查**判断是否相等；
- 都能用 `Definition` 起名字，存进全局环境。

内核不需要分别处理"数"、"类型"和"证明"，它只处理项。
## 5. 是项，不等于良类型
"是项"只说明它在**语法**上合法，不说明它有意义。例如：

```coq
Nat.add true 0
```

它是一个合法的 `App` 节点，所以是项；但内核会拒绝它，因为 `true : bool`，而 `bool` 和 `Nat.add` 要求的 `nat` 不可转换。所以它**不是良类型的**。

更准确的说法是：
- 理论里的所有对象都表示为项；
- 其中**良类型**的项才是有意义的对象，它们都有类型。
## 6. 每个良类型的项都有类型，类型也有类型
"良类型"本来就是指"有类型"。值得注意的是：类型本身也是项，所以**它也有类型**，这条链可以一直往上走：

```text
add_0_r  :  forall n, n + 0 = n  :  Prop  :  Type@{Set+1}  :  Type@{Set+2}  :  …
```

sort 构成一个**无穷的层级**，没有最顶层，所以这条链永远不会断：每个类型都有自己的类型。

为什么不能让 `Type : Type`，即只用一层？因为那样会导致矛盾，这就是 Girard 悖论。分层正是为了避免它。
## 7. 值和规范形式
项不"拥有"一个值，项本身就是那个东西。我们平常说的"值"，是项**算到底**得到的**规范形式**（canonical form），也就是由构造子直接构成的结果：

```coq
Compute double 3.          (* double 3 ⟶ 6，即 S (S (S (S (S (S O))))) *)
Compute (fun n => n) 5.    (* ⟶ 5 *)
```

**规范性**（canonicity）：不加公理时，一个**封闭的**、类型为 `nat` 的良类型项，一定能算到 `O` 或 `S …`。

算不到规范形式的情况：

|情况|例子|是否破坏规范性|
|---|---|---|
|**含自由变量**|`n + 1` 只能算到 `S n`，因为 `n` 不知道是多少|不破坏：规范性只针对封闭项|
|**不透明常量**|`Definition x : nat. exact 3. Qed.` 之后，`Compute x` 停在 `x`|不破坏：定义体存在，只是 `Compute` 不展开以 `Qed` 结束的常量。理论上展开后仍能算出 `3`|
|**公理**|`Axiom a : nat.` 之后，`a` 是一个封闭的 `nat` 项，但它没有定义体，永远算不成具体的数|**破坏**|

## 8. 不是项的东西
Rocq 里也有不是项的东西，它们都不在 `constr` 里，没有类型：

|类别|例子|说明|
|---|---|---|
|**命令**|`Definition`、`Lemma`、`Inductive`、`Check`|vernacular 命令，作用是往环境里加声明，或者查询信息|
|**tactic**|`intro`、`rewrite`、`induction`|构造项的程序，用 Ltac/Ltac2 写成，最终产出一个项|
|**声明**|`nat` 的归纳声明、`add_0_r` 的常量声明|存放在全局环境里的条目。项里出现的 `Ind`、`Const` 只是指向它们|
|**环境和上下文**|全局环境；局部上下文 `n : nat`|项在其中被检查的背景|
|**判断**|`n : nat ⊢ n + 0 : nat`|关于项的陈述，本身不是项|
|**universe 层级**|`Type@{i}` 里的 `i`|不是项，没有类型，不能被函数接收；它们之间的关系由单独的约束图管理|
|**其他**|notation、模块、section、hint 数据库|用于书写和组织，不进入内核项|

## 9. 和 Lean 对比

| |Rocq|Lean|
|---|---|---|
|语法类别|一种：`constr`|一种：`Expr`|
|归纳类型、构造子|单独的 `Ind`、`Construct` 节点|都是 `const`|
|`match`、递归|`Case`、`Fix` 节点|没有节点，用递归子 `rec`（一个常量）|
|`Prop` 的类型|`Type@{Set+1}`|`Sort 1`（即 `Type`）|
|universe 层级是不是项|不是|不是|
|只在构造过程中出现的节点|`Meta`、`Evar`|`fvar`、`mvar`，以及元数据节点 `mdata`|

两边都是"一切皆项"，这也是逐节点翻译能够成立的前提：翻译只需要处理一种东西，也就是项。
## 总结
- 在内核里，数据、函数、类型、命题、证明、sort **都是项**，由固定的十几种节点组合而成。
- "是不是类型"是一种关系：类型为 sort 的项就是类型。
- 因为只有一种类别，项可以当参数、当返回值、出现在类型里，这正是依赖类型的来源。
- 所有项都用同一套规则检查和计算。
- 是项不等于良类型；良类型的项都有类型，靠无穷的 sort 层级，类型的类型也总是存在。
- 命令、tactic、声明本身、环境、判断和 universe 层级都不是项。
