# 逐条保证
目标只是"每条翻译出来的声明都可靠"。翻译正确有两个要求：Lean 接受，以及两边的项逐个节点对应

**① Lean 接受**：每条声明在 Lean 内核里跑一遍就行。

**② 逐个节点对应**：两边的项逐个节点对应（`rel ↔ bvar`、`lam ↔ lam`、`app ↔ app`……），并且每处 level 的调整都有 Rocq 约束作依据。需要建模的有：
- `RTerm`、`LTerm`：写出两边的节点。没有它们，就写不出"这个 Rocq 节点对应那个 Lean 节点"。
- Rocq 的 universe 模型（`RLevel` … `RSort`、`Constraints`、`Sat`）和 Lean 的 `LLevel`：要描述 universe 在 Lean 里怎么调整，两边的 level 都要先写成定义。
- `Corr`：一个关系，逐个节点规定什么叫"对应"。我们要的命题是 `Corr C dR.body dL.body`。
- `REntailsU`：在 universe 节点上要求"调整有 Rocq 约束作依据"。
- 检查器 `checkCorr`：对每条声明实际判断 `Corr` 是否成立。还要**证明一次**它是可靠的（`checkCorr = true → Corr`），否则就只能信任检查器本身。

**③ 类型也对应上**：这不是第三个要求，而是把 ② 用在声明的**类型**上。声明的类型就写在声明里，不需要重新推导：

| |谁保证|
|---|---|
|Rocq：`dR.body : dR.type`|Rocq 内核已经检查过|
|Lean：`dL.body : dL.type`|Lean 内核检查（①）|
|类型对应：`Corr C dR.type dL.type`|`checkCorr`（②）|

三行拼起来，就是"Rocq 和 Lean 给出的类型对应得上"。注意这里只比较**声明的类型**，不比较每个子项的类型。子项在 Lean 里类型对不对，由 ① 中 Lean 内核负责。

**依据 `h` 从哪里来**：调整要有依据，就要证明某条 universe 不等式在 C 下成立：

```lean
h : REntailsU C u v   -- 在约束 C 下，u ≤ v
```

逐条保证时没有 Rocq 的推导可用，所以由检查器**直接从 C 推出**这条不等式。不一定是 C 里原样写着的那条，可能要推一步。例如 C₀ 里写的是 `set < l`，需要的是 `set ≤ l`。检查器的判断也要证明可靠，这对应 audit.py 的 `check_universe_args`。
# 一般性定理
> `RTyping C Γ t T` ⇒ 存在 `t'`、`T'`，使 `Corr t t'`、`Corr T T'`，并且 `LTyping … t' T'`。

它对**所有 Rocq 接受的项**都成立，而不只是测过的那些。
- **不能直接用两边的内核。** Lean 4 的内核是 C++ 写的，Rocq 的内核是 OCaml 写的，都不是 Lean 里能拿来推理的对象。
- **所以要把两边内核的规则写成定义**：Lean 一侧是 `LTyping`、`LEquiv`（怎么判断类型、怎么判断 level 相等），Rocq 一侧是 `RTyping`。证明就是对 `RTyping` 的推导做归纳。
- **`h` 从 Rocq 的推导里来。** 有了 `RTyping`，就有 Rocq 判断类型的完整推导。推导里 cumul 那一步本身就带着前提 `REntails C u v`，翻译时直接拿它当 level 调整的依据：Rocq 在哪里用 cumul，Lean 就在哪里调整。

> **什么是"对 `RTyping` 归纳"**
> 和自然数归纳一样。自然数归纳要证两件事：`0` 成立；`n` 成立则 `n+1` 也成立。
> `RTyping` 的每条规则相当于一种"造项的方式"，归纳就是对**每条规则**证一次：
> - `rel` 规则（没有前提的规则，相当于 `0`）：变量 `rel i` 翻成 `bvar i`，直接成立。
> - `app` 规则（有前提的规则，相当于 `n → n+1`）：**假设** `f` 和 `a` 已经翻译正确、Lean 也接受，**证明** `app f a` 也是这样。
> - `lam`、`prod`、`const`、`cumul` …… 每条同样证一次。
> 每条规则都证完，任何 Rocq 推出来的项就都成立了，因为它的推导就是由这些规则一层层搭起来的。
