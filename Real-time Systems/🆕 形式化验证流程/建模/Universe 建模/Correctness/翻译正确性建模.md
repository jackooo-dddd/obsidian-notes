# Corr：定义逐个节点对应
`Corr E C t t'` 读作：在环境 E、约束 C 下，Rocq 项 `t` 和 Lean 项 `t'` 对应。
对应只要求两件事：两边的形状是否一致，以及每处 universe 调整有没有依据。
## Corr 定义

```lean
inductive Corr (E : REnv) (C : Constraints) : RTerm → LTerm → Prop
  -- 节点对应：形状一样，逐个往下比
  | rel  : Corr E C (.rel i) (.bvar i)
  | sort : Corr E C (.sort s) (.sort (ISort s))
  | prod : Corr E C A A' → Corr E C B B' → Corr E C (.prod A B) (.forallE A' B')
  | lam  : Corr E C A A' → Corr E C t t' → Corr E C (.lam A t) (.lam A' t')
  | app  : Corr E C f f' → Corr E C a a' → Corr E C (.app f a) (.app f' a')

  -- 常量：三种情况
  | constPlain :                                   -- c 没有用到 universe
      E.levels c = [] →
      Corr E C (.const c) (.const c [])
  | constSame :                                    -- 照搬
      E.levels c = [l] →
      Corr E C (.const c) (.const c [ILevel l])
  | constDown :                                    -- 降
      E.levels c = [l] →
      REntailsU C [⟨a, 0⟩] [⟨l, 0⟩] →              -- 依据 h：在 C 下 a ≤ l
      Corr E C (.const c) (.const c [ILevel a])
```
- `E.levels c = [l]`：`E.levels c` 表示 Rocq 中常量 `c` 使用的 Global Universe Level 列表。`[l]` 表示该列表只有一个 Level，即 `l`。这个前提用于确认 Rocq 中常量 `c` 使用的是哪个 Global Level。

## 三条常量规则

|规则|什么时候用|Lean 填的实例|要不要依据|例子|
|---|---|---|---|---|
|`constPlain`|`c` 不涉及 universe|不填|不要|`nat` ↦ `Nat`|
|`constSame`|照搬 Rocq 的 level|`u_l`|不要，`l ≤ l` 总成立|在同样用 `l` 的声明里引用 `id` ↦ `id.{u_l}`|
|`constDown`|填一个更小的 level|`ILevel a`|**要** `h : a ≤ l`|`idNat` 里引用 `id` ↦ `id.{0}`，依据 `set ≤ l`|

- **升、包**：还有 `constUp`（R3↑）和 `lift`（PULift）两种调整，形式和 `constDown` 一样，都要带一条 `h`。
## 用 `idNat` 走一遍

```
idNatR = lam nat (app (app id nat) (rel 0))
idNatL = lam Nat (app (app id.{0} Nat) (bvar 0))
C₀ = [set < l]，E.levels id = [l]，E.levels nat = []
```

从外往里，每个节点都按"要求 / 传入 / 结果"检查：

| 节点                                                           | 用哪条规则                 | 要求                                                 | 传入                            | 结果       |
| ------------------------------------------------------------ | --------------------- | -------------------------------------------------- | ----------------------------- | -------- |
| `lam nat …` ~ `lam Nat …`                                    | `lam`                 | 类型部分、体部分分别对应                                       | 往下比                           | （下面几行都过） |
| `nat` ~ `Nat`                                                | `constPlain`          | `E.levels nat = []`                                | 是                             |          |
| `app (app id nat) (rel 0)` ~ `app (app id.{0} Nat) (bvar 0)` | `app`                 | 函数、参数分别对应                                          | 往下比                           |          |
| `app id nat` ~ `app id.{0} Nat`                              | `app`                 | 同上                                                 | 往下比                           |          |
| `id` ~ `id.{0}`                                              | `constDown`，`a = set` | `E.levels id = [l]`；`ILevel set = 0`；`h : set ≤ l` | `set < l` 在 C₀ 里，推出 `set ≤ l` |          |
| `nat` ~ `Nat`                                                | `constPlain`          | 同上                                                 | 是                             |          |
| `rel 0` ~ `bvar 0`                                           | `rel`                 | 下标相同                                               | 0 = 0                         |          |

只有 `id.{0}` 这一处需要依据，其余都只是形状一致。如果 Lean 写的是 `id.{5}`，`constDown` 要求 `5 ≤ l` 在 C₀ 下成立，推不出来，`Corr` 就不成立。
## 逐条保证和一般性定理 都用同一个 `Corr`

|                       | 逐条保证                                | 一般性定理                                   |
| --------------------- | ----------------------------------- | --------------------------------------- |
| 要证的                   | `Corr E C dR.body dL.body`（以及 type） | 结论里包含 `Corr t t'`、`Corr T T'`           |
| 怎么证                   | 检查器 `checkCorr` 逐个节点走一遍，就是上面那张表     | 对 `RTyping` 归纳，每条 Rocq 规则对应一条 `Corr` 规则 |
| `constDown` 的 `h` 从哪来 | 检查器从 C 直接推出                         | Rocq 推导里 cumul 那一步带着的 `REntails` 前提     |
