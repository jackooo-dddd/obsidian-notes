在 Rocq 中，假设声明 `id` 使用了一个全局 Universe Level `l`。所有引用 `id` 的地方共享同一个 `l`，它没有固定的数值，但必须满足全局约束表 `C`。从数学上说，Rocq 要求声明在**所有满足 C 的 Universe 赋值下**都合法。

翻译到 Lean 后，如果直接把全局 Level `l` 转换为 Universe Parameter `u_l`，那么 `id` 就变成了一个 Universe-Polymorphic Declaration。Lean 不再要求所有引用共享同一个 Level，而是允许每次引用时独立指定 `u_l`，例如 `id.{0}`、`id.{1}`、`id.{2}`。

同时，Lean Kernel 要求这个多态声明对 `u_l` 的**所有合法实例化**都成立，而不只是对满足 Rocq 原有约束 C 的那些赋值成立。因此，这种翻译在 Universe 参数的适用范围上提出了更强的要求：原本只需要在 C 约束下合法的声明，现在需要在 Lean 不受 C 限制的参数取值下也合法。
####  取 `σ := ρ` 就能恢复原声明
- **任取**一个满足约束表 C 的赋值 ρ。在 Lean 里让参数取同样的值：`σ(u_l) = ρ(l)`。
- 核心引理 `I_eval`，在这个 σ 下，翻译后每个 Sort 的值，都等于 Rocq 原来的 Sort 在 ρ 下的值。

所以 Rocq 在 ρ 下的 `id`，就是 Lean 那一族中 `id.{ρ(l)}` 这个成员。ρ 是任取的，所以每个满足 C 的 ρ 都能这样对应上。
- Rocq 证明了"对**所有满足条件的** x，这件事成立"；Lean 证明了"对**所有** x，这件事都成立"。把 Lean 的结论限制到满足条件的 x 上，就回到了 Rocq 的结论。
#### 代价
Lean 要求"对所有取值都正确"，这比 Rocq 的"对满足 C 的取值正确"更强。
例子：`Definition T : Type@{m} := Type@{l}` 依赖约束 `l < m`。翻译后，并不是对所有 `u_l`、`u_m` 都成立，Lean 会拒绝。这时项目要把约束写进 level 表达式：把 `u_m` 解释成 `max(u_m, u_l+1)`。处理后，取 `σ := ρ` 仍然能恢复原声明：ρ 满足 `l < m`，所以 `max(ρ(m), ρ(l)+1) = ρ(m)`。
