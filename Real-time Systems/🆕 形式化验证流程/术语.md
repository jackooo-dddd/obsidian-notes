### 一、推理的起点（不需要证明）

| 说法          | 英文                      | 含义                                          |
| ----------- | ----------------------- | ------------------------------------------- |
| **公理**      | Axiom                   | 不证明、直接承认为真的命题，所有推理都从这里出发                    |
| **定义**      | Definition              | 给一个概念命名并规定它的含义，**不是命题，不存在真假**               |
| **假设 / 前提** | Hypothesis / Assumption | 在某个证明或定理内部临时认定成立的条件，比如"若 b ≥ 0，则……"中的 b ≥ 0 |

### 二、已经证明的结论（按重要性区分）
这些在逻辑上**完全平等**，都是已证明的命题，区别只在作者想强调的地位：

| 说法               | 英文                          | 含义                                                   |
| ---------------- | --------------------------- | ---------------------------------------------------- |
| **定理**           | Theorem                     | 重要的主要结论                                              |
| **主定理**          | Main Theorem                | 整篇论文或整个项目的核心结论                                       |
| **引理**           | Lemma                       | 为证明定理而准备的辅助结论，本身不是重点（例子里的 `step_preserves`）          |
| **辅助引理 / 技术性引理** | Auxiliary / Technical Lemma | 更偏细节、纯粹为了打通某一步的引理                                    |
| **子引理**          | Sublemma                    | 证明某条引理时又需要的更小的引理                                     |
| **推论**           | Corollary                   | 从某个定理**直接、轻松**推出的结论，通常是代入特殊情况（例子里的 `from_zero_safe`） |
| **断言 / 声明**      | Claim                       | 证明**内部**的一个中间结论，通常当场证明，只在这个证明里使用                     |

### 三、形式化验证中特有的说法

| 说法                               | 含义                            |
| -------------------------------- | ----------------------------- |
| **规约**（Specification）            | 系统应该满足的形式化性质，即"要证明什么"         |
| **不变式**（Invariant）               | 在系统每一步执行后都保持成立的性质（例子里的 `Inv`） |
| **前置 / 后置条件**（Pre/Postcondition） | 操作执行前要求成立的条件 / 执行后保证成立的条件     |
| **精化关系**（Refinement）             | 具体层的行为都被抽象层允许                 |
| **证明义务**（Proof Obligation）       | 工具从程序和规约中自动生成的、需要证明的命题        |

## 在 Lean / Rocq 中对应的关键字

| 含义            | Rocq                                                                  | Lean 4                            |
| ------------- | --------------------------------------------------------------------- | --------------------------------- |
| 定理 / 引理 / 推论等 | `Theorem`、`Lemma`、`Corollary`、`Proposition`、`Fact`、`Remark`（**全部等价**） | `theorem`（Mathlib 里还有等价的 `lemma`） |
| 公理            | `Axiom`、`Parameter`                                                   | `axiom`                           |
| 定义            | `Definition`、`Fixpoint`、`Inductive`                                   | `def`、`inductive`、`structure`     |
| 局部假设          | `Hypothesis`、`Variable`                                               | `variable`，或写在定理参数里的 `(h : ...)`  |
| 证明内部的断言       | `assert (H : ...)`                                                    | `have h : ... := ...`             |
| 暂时跳过证明        | `Admitted`                                                            | `sorry`                           |

- **公理和定义是起点，引理是垫脚石，定理是目标，推论是顺带得到的收获。** 证明器内核只认"这个命题有没有被正确证明"，至于叫引理、定理还是推论，都只是写给人看的标签。
